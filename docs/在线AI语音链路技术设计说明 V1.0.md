## 1. 目的与范围

本文规定在线语音链路中音频输入、ASR、规则路由、知识检索、LLM、安全校验、设备命令和TTS的处理顺序、数据边界、异常处理及验证要求。

本文描述研发中心“整链路”及其共用服务端处理链路。CI1302离线识别、真实知识库质量、浴室声学性能和实机TTS播放不在本文中形成测试结论。旧版独立接口`/api/voice/turn`未在本次修订中迁移为多轮会话入口。

当前离线接入采用 CI1302 → STM32，本地固定命令不经C3或云端才能执行。在线语音使用C3独立麦克风；本地命中后不重复触发同一句的在线动作。设备协同事件及协议适配边界见《CI1302经STM32接入与在线离线协同 V1.0》，服务端队列和保留策略见《单机语音调度与数据保留说明 V1.0》。

## 2. 设计目标

1. 固定设备命令优先在CI1302离线执行，不产生在线调用费用。
2. 在线输入优先使用确定性规则和已发布FAQ；其他输入交由LLM处理，相关知识资料作为回答依据。
3. LLM不得直接访问硬件；设备动作必须输出为结构化意图并通过安全校验。
4. 服务端安全校验是预检；ESP32-C3转发至样机主控，实际执行结果以设备回执为准。
5. 各阶段应记录Provider、模型、延迟、费用、结果和错误原因。
6. 生产环境不保存原始音频；研发测试音频必须与生产日志隔离管理。
7. 同一临时会话的规则回复、知识回复与模型回复共享上下文；独立测试和不同设备之间不共享历史。

## 3. 总体处理流程

```text
C3独立Codec设备音频 / 研发板PCM / 文本测试
                  │
                  ▼
              在线ASR
                  │
                  ▼
          唤醒词与会话门控
                  │
                  ▼
       常用指令或固定回复命中？
          ├─ 是 → 结构化设备意图 / 固定回复
          └─ 否
               │
               ▼
         已发布FAQ精确命中？
          ├─ 是 → 直接使用已审核答案
          └─ 否 → LLM（当前输入 + 临时上下文 + 相关知识资料）
                         │
                         ▼
                 服务端安全校验
                    ├─ 控制 → MQTT
                    └─ 文本 → TTS
                         │
                         ▼
                 C3 / 样机主控与执行回执
```

规则和FAQ路径跳过LLM，仍根据请求执行TTS；独立ASR测试不进入后续处理。控制路径须通过安全校验后下发，播报不得替代实际执行回执。

## 4. 输入类型

| 输入类型 | 用途 | ASR阶段 | 备注 |
|---|---|---|---|
| `DEVICE_AUDIO` | C3独立Codec采集的设备音频 | 执行 | 唤醒后建立临时会话，离线命中则丢弃 |
| 浏览器/测试音频 | ASR和链路研发测试 | 执行 | 仅用于研发环境 |
| 文本模拟 | 规则、知识库、LLM和安全测试 | 跳过 | 不代表ASR测试 |
| CI1302语义ID | 离线固定命令 | 不执行 | 目标量产路径，待样板适配 |

## 5. ASR处理

ASR接口由`speech.service.ts`统一封装。调用参数至少包括音频Base64、MIME类型和可选Provider ID。未指定Provider时使用研发中心配置的默认ASR Provider。

ASR输出包括：

- 状态：`COMPLETED`、`NOT_CONFIGURED`或`FAILED`；
- Provider ID及名称；
- 识别文本；
- 调用延迟；
- 费用估算；
- 错误信息。

ASR未返回有效文本时，链路不得进入设备语义解析，不得生成设备命令。

当前`ASR_ONLY`测试模式在识别后直接返回，不执行规则、LLM和设备控制，用于隔离验证ASR结果。

## 6. 唤醒词与会话门控

产品唤醒词为“小东小东”。在线测试链路对空格及常见中英文标点进行归一化后判断唤醒词。新会话要求唤醒词但未检测到时：

- 路由结果为`UNRESOLVED`；
- 安全决策为不执行；
- 不生成MQTT设备命令；
- 不进入LLM补偿识别。

当前在线唤醒词判断仅用于研发链路门控，不等同于CI1302本地唤醒性能。

### 6.1 临时会话

- 首轮只有唤醒词时回复“我在”；唤醒词与问题连说时直接处理问题。同一会话后续轮不要求重复唤醒。
- 每次请求返回`conversationId`；研发中心文字测试携带该ID续接，设备音频请求可自动续接当前设备最近的整链路会话。
- 会话空闲5分钟后过期；“再见”“结束对话”等独立结束语关闭会话；研发中心提供“新建会话”按钮主动清空。
- 整链路和单项LLM测试分别维护上下文，按设备隔离；批量测试每条使用独立上下文，避免前一条污染后一条。
- 最多保留最近12轮，合计不超过12000字符；同一会话请求按顺序处理。模型失败的轮次不写入上下文。
- 历史包含用户输入、实际回复及命令执行状态；预览指令标记为`NOT_EXECUTED`，不能作为设备已执行的依据。

当前会话存储为单API进程内存，进程重启后清空，最多保留1000个会话。正式部署多API进程时须迁移至Redis，实现统一过期、隔离及请求顺序控制。

### 6.2 录音窗口边界

当前立创板仍由研发中心按钮发起单次6秒录音。多次点击可延续同一会话上下文，但尚未实现自动连续收音、VAD自动断句、播报打断或连续待机唤醒。不能据此认定完整免按键交互已验证。

## 7. 确定性规则路由

规则层处理能够直接映射的设备控制表达，包括照明、吹风、换气、弱暖、强暖、摆风、干燥、待机和目标温度等。规则命中时生成统一`AiResult`：

- `resultType`；
- `intent`；
- 参数槽位；
- 播报文本；
- 是否需要确认。

规则命中路径标记为`ONLINE_RULE`。该路径不调用LLM，但仍执行安全校验。

设备控制采用归一化后的完整短句匹配，不按子串直接触发。“不要打开照明”“打开照明了吗”以及组合指令均交由LLM解释。问候、感谢、结束语及基础助手介绍使用固定回复；感谢不结束会话。

## 8. 知识库路由

### 8.1 当前实现

当前知识库支持文档标题、分类、正文、标签和发布状态。语音链路采用两级处理：

1. 当前问题与已发布文档标题在去除空格、常见标点后完全一致，且正文不超过600字符时，将正文作为FAQ答案直接返回，不调用LLM。
2. 其他问题按标题、标签、分类检索相关资料，最多3篇、每篇最多3000字符、合计最多8000字符，交给LLM结合当前问题和会话历史组织回答。当前问题缺少检索关键词时，允许使用最近3条用户问题检索资料，但不能直接沿用上一问题的FAQ答案。

当前实现属于本地关键词检索，不应描述为已完成向量检索或生产级RAG。正式知识资料尚未取得，知识回答质量尚未验证。

### 8.2 文档分类

- 产品信息；
- 安装；
- 使用；
- 故障排查；
- 售后；
- 保养维护；
- 其他。

只有状态为`PUBLISHED`的文档参与检索。未命中时仍进入LLM：普通对话正常回答；产品参数、维修方法、故障和售后规则缺少资料时须明确说明，不能编造。

本次修订时知识库未录入正式资料。FAQ路由已通过模拟测试，不代表正式产品问题已经能够直接回答。

### 8.3 正式资料接入要求

东信提供的知识文件必须标识资料名称、适用型号、版本、生效日期和发布状态。导入前应拆分为可独立引用的知识条目，并保留来源文档及章节定位。

知识库专项测试必须验证正确文档命中、必含要点、禁止内容、无资料时的拒答及型号边界。

## 9. LLM处理

规则和精确FAQ未处理的输入进入LLM。LLM接收同一临时会话的历史消息、当前设备状态及检索到的知识资料，必须输出符合共享Schema的结构化结果，不得把自然语言回复直接转换为硬件电平。

LLM模块输出至少包括：

- 结果类型：设备控制、售后问答或普通对话；
- 设备意图或空值；
- 参数槽位；
- 用户播报文本；
- 是否需要确认；
- Token及费用信息；
- 解析或调用错误。

Provider未显式指定时使用研发中心保存的默认LLM Provider。模型返回无法通过Schema解析时，本次请求应失败或降级为不执行，不得构造猜测性设备动作。

普通对话等非控制结果的`intent`必须为JSON `null`，不是字符串`"null"`或自定义对话枚举；`slots`为空对象，`requiresConfirm`为`false`。服务端对已知非控制类型统一清空设备动作字段。`DEVICE_CONTROL`的`intent`必须属于设备指令枚举，不接受未知值，也不将其猜测映射为有效指令。

输出协议由服务端附加在提示词后，第三方Provider自定义请求参数不得覆盖消息、模型和JSON格式约束。响应被截断、不是完整JSON或字段不合规时，页面显示具体错误，设备不执行。

## 10. 安全校验与设备下发

所有设备控制结果必须经过服务端规则检查，至少验证：

- 意图是否属于产品已启用能力；
- 参数是否在允许范围内；
- 当前状态是否允许动作；
- 是否需要用户确认；
- 是否存在高风险或冲突动作。

安全决策允许执行且请求明确要求执行时，服务端将意图转换为设备动作，创建命令记录并通过MQTT下发。设备侧按照现有C3与样机主控的控制链路处理。研发中心“文字验证”和单项“LLM对话”不下发设备动作。

设备未回执、拒绝或执行失败时，服务端不得仅根据MQTT发布成功把命令标记为已执行。

## 11. TTS处理

TTS输入使用安全校验后的播报文本。以下情况不调用云端TTS：

- 离线固定命令已由CI1302处理；
- 测试请求显式设置不合成语音；
- ASR独立测试；
- 链路在前置阶段失败且无有效播报文本。

TTS输出包括Provider、音频Base64、MIME类型、延迟、费用和错误信息。批量TTS测试只生成音频文件，不自动发送开发板播放。

实板播放必须满足：用户主动发起、二次确认、功放默认关闭、单次播放、可立即停止和无上电自动播放。

## 12. Provider配置

研发中心分别维护ASR、LLM和TTS默认Provider。配置项包括Provider启用状态、模型ID、服务地址、超时、TTS音色和API Key状态。

API Key只写入服务端本地环境文件，不通过查询接口回显，不得提交Git。生产部署时应迁移至受控密钥服务。

默认配置可在“设置 → AI服务”修改。研发中心语音验证页展示当前生效的ASR、LLM、TTS模型；专项测试报告必须记录实际使用的Provider、模型和配置版本，不以本文固定型号代替运行时配置。

## 13. 记录与数据保留

研发批量测试记录包括任务、数据集、Provider、逐条输入、期望结果、实际结果、通过状态、延迟、费用和错误。ASR研发音频存储在独立测试产物目录，不与生产日志混用。

生产环境只保留文本、意图、路由、命令回执、费用和必要错误元数据，默认保存90天，不保存原始音频。自动清理机制尚未实现，属于生产化工作项。

## 14. 异常处理

| 异常 | 处理要求 |
|---|---|
| ASR未配置或失败 | 终止语义处理，不下发设备命令 |
| 新会话缺少唤醒词且要求唤醒 | 不执行，不调用LLM猜测唤醒意图；有效会话内不重复要求 |
| 规则未命中 | 继续知识或LLM路由 |
| 知识库未命中 | 继续LLM对话；涉及产品事实时说明资料不足，不编造 |
| LLM超时或格式错误 | 不执行设备动作，记录错误 |
| 安全校验拒绝 | 不下发MQTT，返回拒绝原因 |
| MQTT未连接 | 命令保持失败/待处理状态，不声明已执行 |
| TTS失败 | 保留文本结果，不影响已经确认的设备命令状态 |

## 15. 当前验证边界

本次软件检查包括17项后端自动测试，以及1440px桌面、390px手机页面模拟检查。覆盖规则与FAQ跳过LLM、未命中进入LLM、上下文续接、会话重置与过期、不同设备和测试类型隔离、非法模型输出拒绝、错误显示和禁止自动播放。

本次检查中模型、音频和设备副作用均被模拟，未发起真实录音、语音播放或样机动作；不能据此推导云端模型准确率或实板语音效果。下列结论尚未形成：

- 正式ASR数据集准确率；
- “小东小东”本地唤醒命中率；
- 浴室噪声和远场识别性能；
- 正式知识库回答正确率；
- LLM综合语义准确率和安全拒绝率；
- TTS主观音质、响度和实板播放稳定性；
- 最终双麦样板上的CI唤醒、C3独立Codec录音和在线音频闭环。

CI1302不作为在线PCM来源。设备在线音频由C3独立Codec和麦克风采集，详细边界见[CI1302离线语音与独立在线音频方案 V1.0](CI1302离线语音与独立在线音频方案%20V1.0.md)。

上述项目必须按[AI语音专项测试计划与数据集规范 V1.0](AI语音专项测试计划与数据集规范%20V1.0.md)执行后形成专项测试报告。
