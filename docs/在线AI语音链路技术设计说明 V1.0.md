## 1. 目的与范围

本文规定在线语音链路中音频输入、ASR、规则路由、知识检索、LLM、安全校验、设备命令和TTS的处理顺序、数据边界、异常处理及验证要求。

本文描述当前服务端实现和目标链路。CI1302离线识别、真实知识库质量、浴室声学性能和实机TTS播放不在本文中形成测试结论。

## 2. 设计目标

1. 固定设备命令优先在CI1302离线执行，不产生在线调用费用。
2. 在线输入优先使用确定性规则和知识库，只有未命中内容进入LLM。
3. LLM不得直接访问硬件；设备动作必须输出为结构化意图并通过安全校验。
4. 服务端安全校验是预检，ESP32-C3本地状态机拥有最终执行权。
5. 各阶段应记录Provider、模型、延迟、费用、结果和错误原因。
6. 生产环境不保存原始音频；研发测试音频必须与生产日志隔离管理。

## 3. 总体处理流程

```text
C3独立Codec设备音频 / 研发板PCM / 文本测试
                  │
                  ▼
              在线ASR
                  │
                  ▼
          唤醒词与会话门控
                  │
                  ▼
       明确设备规则是否命中？
          ├─ 是 → 结构化设备意图
          └─ 否
               │
               ▼
         是否属于知识问题？
          ├─ 是 → 知识检索与受控回答
          └─ 否 → LLM结构化输出
                         │
                         ▼
                 服务端安全校验
                    ├─ 控制 → MQTT
                    └─ 文本 → TTS
                         │
                         ▼
                  C3本地安全终审
```

## 4. 输入类型

| 输入类型 | 用途 | ASR阶段 | 备注 |
|---|---|---|---|
| `DEVICE_AUDIO` | C3独立Codec采集的设备音频 | 执行 | 唤醒后建立临时会话，离线命中则丢弃 |
| 浏览器/测试音频 | ASR和链路研发测试 | 执行 | 仅用于研发环境 |
| 文本模拟 | 规则、知识库、LLM和安全测试 | 跳过 | 不代表ASR测试 |
| CI1302语义ID | 离线固定命令 | 不执行 | 目标量产路径，待样板适配 |

## 5. ASR处理

ASR接口由`speech.service.ts`统一封装。调用参数至少包括音频Base64、MIME类型和可选Provider ID。未指定Provider时使用研发中心配置的默认ASR Provider。

ASR输出包括：

- 状态：`COMPLETED`、`NOT_CONFIGURED`或`FAILED`；
- Provider ID及名称；
- 识别文本；
- 调用延迟；
- 费用估算；
- 错误信息。

ASR未返回有效文本时，链路不得进入设备语义解析，不得生成设备命令。

当前`ASR_ONLY`测试模式在识别后直接返回，不执行规则、LLM和设备控制，用于隔离验证ASR结果。

## 6. 唤醒词与会话门控

产品唤醒词为“小东小东”。在线测试链路对空格及常见中英文标点进行归一化后判断唤醒词。请求要求唤醒词但未检测到时：

- 路由结果为`UNRESOLVED`；
- 安全决策为不执行；
- 不生成MQTT设备命令；
- 不进入LLM补偿识别。

当前在线唤醒词判断仅用于研发链路门控，不等同于CI1302本地唤醒性能。

## 7. 确定性规则路由

规则层处理能够直接映射的设备控制表达，包括照明、吹风、换气、弱暖、强暖、摆风、干燥、待机和目标温度等。规则命中时生成统一`AiResult`：

- `resultType`；
- `intent`；
- 参数槽位；
- 播报文本；
- 是否需要确认。

规则命中路径标记为`ONLINE_RULE`。该路径不调用LLM，但仍执行安全校验。

## 8. 知识库路由

### 8.1 当前实现

当前知识库支持文档标题、分类、正文、标签和发布状态。系统通过问题中的关键词判断是否进入知识路由，并按照标题、标签和分类的确定性匹配分值返回候选文档和正文片段。

当前实现属于本地关键词检索，不应描述为已完成向量检索或生产级RAG。正式知识资料尚未取得，知识回答质量尚未验证。

### 8.2 文档分类

- 产品信息；
- 安装；
- 使用；
- 故障排查；
- 售后；
- 保养维护；
- 其他。

只有状态为`PUBLISHED`的文档参与检索。未命中时返回统一兜底内容，不得基于未知资料推断产品参数、维修方法或安全结论。

### 8.3 正式资料接入要求

东信提供的知识文件必须标识资料名称、适用型号、版本、生效日期和发布状态。导入前应拆分为可独立引用的知识条目，并保留来源文档及章节定位。

知识库专项测试必须验证正确文档命中、必含要点、禁止内容、无资料时的拒答及型号边界。

## 9. LLM处理

规则和知识路由未处理的输入进入LLM。LLM必须输出符合共享Schema的结构化结果，不得把自然语言回复直接转换为硬件电平。

LLM模块输出至少包括：

- 结果类型：设备控制、售后问答或普通对话；
- 设备意图或空值；
- 参数槽位；
- 用户播报文本；
- 是否需要确认；
- Token及费用信息；
- 解析或调用错误。

Provider未显式指定时使用研发中心保存的默认LLM Provider。模型返回无法通过Schema解析时，本次请求应失败或降级为不执行，不得构造猜测性设备动作。

## 10. 安全校验与设备下发

所有设备控制结果必须经过服务端规则检查，至少验证：

- 意图是否属于产品已启用能力；
- 参数是否在允许范围内；
- 当前状态是否允许动作；
- 是否需要用户确认；
- 是否存在高风险或冲突动作。

安全决策允许执行时，服务端将意图转换为设备动作，创建命令记录并通过MQTT下发。设备收到命令后再次通过本地命令队列和安全状态机执行。

设备未回执、拒绝或执行失败时，服务端不得仅根据MQTT发布成功把命令标记为已执行。

## 11. TTS处理

TTS输入使用安全校验后的播报文本。以下情况不调用云端TTS：

- 离线固定命令已由CI1302处理；
- 测试请求显式设置不合成语音；
- ASR独立测试；
- 链路在前置阶段失败且无有效播报文本。

TTS输出包括Provider、音频Base64、MIME类型、延迟、费用和错误信息。批量TTS测试只生成音频文件，不自动发送开发板播放。

实板播放必须满足：用户主动发起、二次确认、功放默认关闭、单次播放、可立即停止和无上电自动播放。

## 12. Provider配置

研发中心分别维护ASR、LLM和TTS默认Provider。配置项包括Provider启用状态、模型ID、服务地址、超时、TTS音色和API Key状态。

API Key只写入服务端本地环境文件，不通过查询接口回显，不得提交Git。生产部署时应迁移至受控密钥服务。

当前开发默认配置为：

| 类型 | Provider ID | 用途 |
|---|---|---|
| ASR | `aliyun-qwen3-asr-flash` | 在线语音识别 |
| LLM | `aliyun-qwen3-7-flash` | 结构化语义和对话 |
| TTS | `aliyun-cosyvoice-v3-flash` | 动态语音合成 |

默认配置可修改，专项测试报告必须记录实际使用的Provider、模型和配置版本。

## 13. 记录与数据保留

研发批量测试记录包括任务、数据集、Provider、逐条输入、期望结果、实际结果、通过状态、延迟、费用和错误。ASR研发音频存储在独立测试产物目录，不与生产日志混用。

生产环境只保留文本、意图、路由、命令回执、费用和必要错误元数据，默认保存90天，不保存原始音频。自动清理机制尚未实现，属于生产化工作项。

## 14. 异常处理

| 异常 | 处理要求 |
|---|---|
| ASR未配置或失败 | 终止语义处理，不下发设备命令 |
| 缺少唤醒词 | 不执行，不调用LLM猜测唤醒意图 |
| 规则未命中 | 继续知识或LLM路由 |
| 知识库未命中 | 返回统一兜底，不编造产品事实 |
| LLM超时或格式错误 | 不执行设备动作，记录错误 |
| 安全校验拒绝 | 不下发MQTT，返回拒绝原因 |
| MQTT未连接 | 命令保持失败/待处理状态，不声明已执行 |
| TTS失败 | 保留文本结果，不影响已经确认的设备命令状态 |

## 15. 当前验证边界

当前已具备ASR、LLM和TTS服务接口连通能力，以及文本条件下的路由和结构化处理实现。下列结论尚未形成：

- 正式ASR数据集准确率；
- “小东小东”本地唤醒命中率；
- 浴室噪声和远场识别性能；
- 正式知识库回答正确率；
- LLM综合语义准确率和安全拒绝率；
- TTS主观音质、响度和实板播放稳定性；
- 最终双麦样板上的CI唤醒、C3独立Codec录音和在线音频闭环。

CI1302不作为在线PCM来源。设备在线音频由C3独立Codec和麦克风采集，详细边界见[CI1302离线语音与独立在线音频方案 V1.0](CI1302离线语音与独立在线音频方案%20V1.0.md)。

上述项目必须按[AI语音专项测试计划与数据集规范 V1.0](AI语音专项测试计划与数据集规范%20V1.0.md)执行后形成专项测试报告。
