# 单台 ECS 试点部署边界与准备 V0.1

更新日期：2026-11-02  
状态：已确认杭州 ECS，Alibaba Cloud Linux 3，4 核 / 8 GB / 60 GB / 5 Mbps；运维网页/API 已在回环试点部署。2026-11-03 公共 DNS 已解析 `ops.zjdongxin.net`，`api` 记录仍待添加；实名认证状态需在阿里云控制台核对，ICP备案与 HTTPS 证书待办。具体发布与更新流程见 [运维平台单机试点发布](../deploy/README.md)。

## 当前决策

第一阶段可以不购买 RDS。在同一台 ECS 上运行 PostgreSQL、API、MQTT Broker 和运营平台，以降低固定费用。PostgreSQL 是持久化数据库，不等同于现有 JSON 文件；它与应用共用 ECS 的 CPU、内存和磁盘，也共用单机故障风险。以后需要迁至 RDS 时，应用仍使用同一套 PostgreSQL schema 和迁移文件。

这只是样机及有限设备数的试点拓扑，不是十万台设备的容量承诺。当前 API 的设备、命令、知识库等业务主路径仍依赖 JSON/进程状态，生产启动门禁不会因安装 PostgreSQL 而自动解除；不能将现有 JSON 模式作为正式消费者服务发布。

## 部署拓扑

```text
样机 ESP32-C3 -- HTTPS / MQTTS -- 公网域名
                                  |
                       ECS 反向代理 / TLS 入口
                                  |
                   API + MQTT Broker + 运营平台
                                  |
                         127.0.0.1:5432
                             PostgreSQL
                                  |
                    离机备份 + 定期恢复验证
```

研发中心只用于内部测试，暂不作为公网消费者入口。原始音频不入库，只保存必要的文本记录，默认保留 90 天。数据库服务只监听回环地址，不开放公网 5432；应用和 Broker 使用独立的最小权限数据库账号。PostgreSQL 本机连接显式配置 `DATABASE_TLS_MODE=local` 且 `DATABASE_URL` 的主机必须是 `127.0.0.1`。远程数据库使用默认 `verify-ca` 模式及 `DATABASE_CA_FILE`，不得关掉证书校验。

## ECS 信息确认后执行

1. 核对 ECS 地域、系统、CPU/内存、系统盘与数据盘、带宽、快照能力和域名备案状态，据此确定进程内存限额与磁盘布局。没有确认这些参数前不安装或迁移数据库。
2. 配置 DNS、HTTPS 与 MQTTS 证书；安全组只开放必要的 443、8883，以及受限运维来源的 22。80 仅在证书申请或跳转需要时开放。不要开放 1883、3077、5432 或数据库管理端口。
3. 在 ECS 本机安装 PostgreSQL，限制为 `127.0.0.1` 访问，建立专用数据库和账号。数据盘优先独立；无独立数据盘时必须明确磁盘空间和可恢复备份方案。数据库备份必须离开这台 ECS，并实际演练恢复，单靠同机文件副本不算备份。
4. 先运行只读迁移计划，再在已备份的数据库中执行迁移。逐项接入设备、命令、状态、知识库、审计等业务仓储，并验证重启后的状态与命令幂等；不能只建表就关闭 JSON 生产门禁。
5. 完成设备独立密钥灌装、后台认证、MQTTS/HTTPS、限流、日志脱敏、备份恢复和小规模真实样机联调后，再评估试点放量。十万台目标需要按实际心跳与语音峰值做容量测试，并制定数据库或服务拆分条件。

## 当前可执行的本地检查

- `npm run verify:db`：仓储与迁移单元测试，不连接真实 PostgreSQL。
- `npm run verify:runtime`：API 时序、安全与语音链路软件回归，不控制硬件。
- `npm run db:plan -w @dongxin/api`：只读列出迁移版本，不连接数据库。

这些检查不能代替真实 PostgreSQL SQL、事务隔离、备份恢复或整机联调验收。旧的《云端数据库迁移与试点准备 V0.1》按购买 RDS 的前提编写；本文件对第一阶段数据库部署位置的决策优先，现有迁移及上线门禁要求仍然有效。
