## 一、验收总则

### 1. 验收依据

本附件作为《东信智能浴霸 AI 大模型融合创新项目》技术开发（委托）合同的组成部分，与主合同具有同等效力。

本项目验收依据包括：

1. 主合同第一条约定的项目技术目标及技术内容；
2. 主合同第十三条约定的验收标准；
3. 本附件约定的验收模块、量化指标、测试方法、测试用例及验收记录；
4. 甲方提供并经双方确认的浴霸样机、主控通信协议、产品资料、知识库资料、测试账号及其他项目资料；
5. 双方在项目实施过程中以书面形式确认的需求、接口、测试条件及变更内容。

### 2. 验收主体与程序

1. 乙方完成约定研发内容并提交交付成果后，向甲方发出验收申请。
2. 甲方应在收到交付成果之日起 **15个工作日** 内组织验收，并向乙方出具书面验收意见。
3. 甲方验收意见应明确列出通过项、未通过项及对应的事实依据。甲方未在前述期限内提出书面异议的，视为本项目验收通过。
4. 如验收未通过，甲方应一次性列明未达标条款、测试结果及整改要求。乙方应在收到完整书面整改要求之日起 **10个工作日** 内完成整改并申请复验。
5. 复验仅针对已列明的未达标项进行。因甲方新增需求、测试条件变化、硬件或第三方服务变化导致的新增工作，不属于本附件约定的整改范围。
6. 验收应以真实样机联调、系统现场演示、测试记录及本附件规定的测试结果为主要依据。

### 4. 指标口径定义

#### 4.1 可用率

可用率是指在约定统计周期内，AI服务端能够正常接收并处理测试请求、返回有效结果的请求次数，占请求总数的比例。

计算公式：

```text
可用率 = 正常响应请求次数 ÷ 请求总数 × 100%
```

统计周期默认连续 **7×24小时**；如双方另有书面约定，以双方确认的统计周期为准。因甲方网络、样机、主控、语音模块、服务器资源或第三方服务故障造成的不可用，应在测试记录中单独标注。

#### 4.2 端到端响应时间

端到端响应时间是指用户发出语音或指令开始，到设备完成对应动作或系统完成有效反馈的全程耗时。

语音控制场景的计时起点为语音模块或测试系统确认收到有效用户输入的时间，终点为以下任一时间：

1. 设备完成对应控制动作并返回执行结果的时间；
2. 系统向语音模块或小程序返回有效播报文本、对话结果或明确失败提示的时间。

主动沟通场景的计时起点为服务端收到有效雷达/人感事件的时间，终点为系统返回主动沟通文本或完成约定控制流程的时间。

#### 4.3 语料通过率

语料通过率是指在指定测试语料中，系统正确识别用户表达、映射为约定控制意图，并输出正确参数及结果的语料条数，占测试语料总条数的比例。

计算公式：

```text
语料通过率 = 通过语料条数 ÷ 有效测试语料总条数 × 100%
```

#### 4.4 高风险动作

高风险动作是指涉及浴霸运行安全、人员安全、设备保护或可能造成较大影响的控制指令。具体动作清单以本附件模块7中的双方确认版本为准。

#### 4.5 日志完整率

日志完整率是指关键交互过程中，按约定应记录的日志条数中，实际成功写入系统并可查询的日志条数所占比例。

计算公式：

```text
日志完整率 = 已成功记录并可查询的日志条数 ÷ 应记录日志总条数 × 100%
```

关键日志至少应覆盖用户输入、识别结果、意图判断、模型调用、规则校验、控制下发、设备执行结果及异常信息。

#### 4.6 指令下发成功率

指令下发成功率是指在样机在线、主控通信协议有效、通信链路正常的条件下，服务端成功生成并下发至设备接入层的控制指令次数，占应下发控制指令总次数的比例。

设备底层执行结果应在测试记录中单独记录。因甲方主控、硬件线路、设备执行机构或通信协议实现问题导致的执行失败，应单独标注原因。

#### 4.7 准确率

准确率是指测试问题中，系统返回内容与双方确认的标准答案或预期结果一致，且满足知识来源、动作参数及安全要求的问题条数，占有效测试问题总条数的比例。

### 1. 测试结果记录要求

每项测试至少应记录以下内容：

1. 测试日期、测试人员、测试环境及使用的样机；
2. 测试输入、预期结果及实际结果；
3. 是否调用规则、模型或知识库；
4. 是否生成设备控制指令；
5. 安全规则校验结果；
6. 设备执行结果或系统反馈结果；
7. 响应时间、错误信息及相关日志编号；
8. 未通过项的原因、责任归属及整改情况。

### 2. 测试通过判定

1. 单项测试按照本附件对应的通过标准判定。
2. 百分比指标以有效测试总数为统计基数，测试无效、因测试环境异常无法完成的记录应说明原因，不得直接计入通过项。
3. 需要真实样机联调的项目，以设备在线、通信协议有效且甲方主控能够正常响应为测试前提。
4. 需要第三方模型、ASR、TTS、服务器或网络服务支持的项目，以相关服务正常可用为测试前提。
5. 现场验收时，甲方如对测试结果提出异议，应在验收记录中写明具体测试项、实际结果和异议理由。
