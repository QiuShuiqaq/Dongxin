## 1. 方案结论

本项目采用离线语音与在线音频分离方案：

- CI1302只负责“小东小东”唤醒、固定命令离线识别和语义ID输出；
- ESP32-C3通过独立音频Codec和独立麦克风取得在线语音PCM；
- 在线ASR、规则、知识库、LLM和TTS仍由C3与服务端协同完成；
- 动态TTS、本地“我在”和断网提示均由C3音频链路播放；
- CI1302不向C3传输PCM，不输出任意自然语言文本，也不直接控制STM32或负载；
- 首版采用两个麦克风，不直接并联同一个模拟麦克风。

CI1302的I2S外设能力不再作为量产链路前置条件。后续即使厂商证明可以导出PCM，也只作为降本预研，不改变首版基线。

## 2. 总体架构

```text
麦克风A
   │
   ▼
CI1302 ── UART事件/语义ID ──┐
  唤醒、离线固定命令          │
                            ▼
麦克风B ── 音频Codec ── I2S ── ESP32-C3 ── UART ── 现有STM32
                              │                    负载/温控/安全
                              │ Wi-Fi
                              ▼
                    ASR / 规则 / 知识库 / LLM / TTS
                              │
                              ▼
扬声器 ◀── 功放 ◀── 音频Codec ◀── ESP32-C3
```

推荐沿用立创ESP32-C3音频板已使用的软件路径，以ES8311类全双工Codec作为首版参考。最终Codec、功放和麦克风料号由硬件原理图及BOM评审冻结。

## 3. 模块职责

| 模块 | 必须承担 | 不承担 |
|---|---|---|
| CI1302 | 常驻唤醒、固定命令识别、语义ID、识别状态 | PCM上传、任意语句转文字、动态TTS、负载控制 |
| ESP32-C3 | 音频缓存、会话状态、联网、在线AI、TTS播放、命令校验、STM32适配 | 热安全和功率负载直接控制 |
| 音频Codec | 麦克风B采集、PCM输入输出、扬声器播放通路 | 唤醒词和语义判断 |
| STM32 | 现有负载、电机、温控、显示、遥控和安全互锁 | ASR、LLM和联网业务 |
| 服务端 | ASR、规则、知识库、LLM、TTS和记录 | 绕过设备安全规则直接操作硬件 |

## 4. 硬件接口基线

### 4.1 CI1302与C3

CI1302与C3之间只要求低带宽数字控制接口：

- 3.3V TTL UART；
- `CI_TX -> C3_RX`为必选，用于唤醒、语义ID和状态；
- `C3_TX -> CI_RX`建议保留，用于查询、诊断和后续资源管理；
- 双方共地；
- CI1302独立保留烧录、BOOT、RESET和日志测试点；
- 不为CI1302到C3的PCM传输分配I2S引脚。

UART线上格式优先服从启英泰伦官方固件和资源工具。项目适配层把厂商命令码映射为统一事件，不为追求自定义协议而重写CI1302底层固件。

### 4.2 C3在线音频

C3在线音频链路至少包括：

- 独立麦克风B；
- 音频Codec；
- C3与Codec之间的I2S；
- Codec配置总线，通常为I2C；
- 独立功放使能或静音控制；
- 单个产品扬声器。

首版必须保留Codec、功放、麦克风和I2S测试点。功放上电默认关闭或静音，只有明确播放动作才能开启。

### 4.3 双麦克风

麦克风A供CI1302离线识别，麦克风B供C3在线音频。两个麦克风应位于同一拾音区域，并在结构设计中避免风道直吹、扬声器正反馈和明显遮挡。

首版不得把一个模拟麦克风直接并联到CI1302和Codec。若后续需要降本为单麦，必须由硬件工程师完成偏置、输入阻抗、缓冲/隔离和噪声评审，并重新进行唤醒率及ASR测试。

## 5. 会话流程

### 5.1 固定命令

```text
用户说“小东小东，打开暖风”
  -> CI1302识别唤醒和固定命令
  -> UART上报语义ID
  -> C3校验语义、状态和安全规则
  -> C3通过STM32协议下发动作
  -> STM32真实状态回传后，C3播放本地确认音
  -> 不调用在线ASR/LLM/TTS
```

### 5.2 在线自然语言

```text
CI1302上报WAKE
  -> C3从独立Codec音频环形缓冲取得唤醒前后语音
  -> C3开始临时上传会话
  -> CI1302未输出固定语义ID，或识别超时
  -> 服务端提交在线ASR
  -> 规则 / 知识库 / LLM
  -> 安全校验
  -> 设备控制或TTS回复
```

C3音频链路应常驻短时环形缓冲。16kHz、16bit、单声道PCM每秒约32KB，首版建议从约1秒预录开始实测，具体长度以C3可用内存和不丢句首测试确定。

为了降低固定命令的在线费用，C3可在唤醒后把音频上传到服务端临时缓冲，但暂不调用ASR：

- 收到离线语义ID：取消并丢弃临时音频；
- 离线未命中或超时：提交临时音频给ASR；
- 生产环境临时音频在会话结束后立即删除，不进入90天文本日志。

### 5.3 唤醒反馈

首版支持两种说法：

- 分句：“小东小东”后停顿，C3播放本地“我在”，再进入命令采集；
- 连续句：“小东小东打开暖风”，检测到唤醒后语音仍连续时，不插入“我在”，避免遮挡后半句。

实现时可在WAKE后设置短暂判断窗口，结合独立音频能量或可用的CI VAD事件判断是否继续说话。该窗口、阈值及提示时机必须通过样板实测调整。

### 5.4 断网

- 固定命令仍由CI1302识别，经C3和STM32执行；
- 非固定命令无法进入在线ASR；
- C3使用本地音频资源播放“网络未连接，请使用固定指令”；
- 无论是否联网，CI1302都不得绕过C3直接操作负载。

### 5.5 播放期间

第一版采用半双工：TTS或本地提示播放期间暂停在线采音提交，并忽略可能由扬声器回声造成的CI唤醒/命令事件。播放结束后重新进入待唤醒状态。

## 6. 离线语义范围

离线词表只覆盖高频、明确、可安全执行的控制语义，例如：

- 照明开关；
- 吹风、换气；
- 弱暖、强暖和关闭取暖；
- 摆风、干燥；
- 目标温度；
- 全部关闭。

多种口语表达可以映射到同一个语义ID。实际词条数量、相似词冲突和资源占用以CI1302资源工具及样板识别结果为准，不预先承诺任意自然语言能力。

## 7. 实施顺序

1. 使用现有立创板继续验证Codec录音、在线ASR和受控TTS播放；
2. CI1302独立验证“小东小东”、固定命令、UART输出和断网工作；
3. 在组合样板上接入双麦克风、CI UART和C3独立Codec；
4. 实现C3会话状态机、预录缓冲、离线命中取消在线会话及超时转ASR；
5. 接入现有STM32协议，先验证照明等低风险动作和真实状态回执；
6. 验证分句/连续句、半双工、断网、重启、串口异常和长时间运行；
7. 冻结硬件料号、UART码表、离线资源包和量产测试方法。

## 8. 验收边界

以下结果必须分别形成证据，不能相互替代：

- CI1302唤醒和离线命令测试；
- C3独立麦克风录音及ASR测试；
- C3 Codec、功放和扬声器播放测试；
- CI UART语义ID到C3统一命令的映射测试；
- C3到STM32动作及真实状态回执测试；
- 断网固定命令和非固定命令提示测试；
- 分句和连续句的完整会话测试；
- 浴室风噪、距离、回声和安装结构下的整机测试。

当前立创板测试只能证明C3独立音频链路的研发可行性，不能替代最终双麦组合样板和整机声学验收。
