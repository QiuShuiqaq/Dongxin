# 东信智能浴霸项目范围与技术决策基线 V1.0

更新日期：2026-09-14
状态：已确认研发基线

本文档是后续研发的执行入口。旧文档、旧STM32源码和《东信浴霸 MCU 串口协议 V0.2》只作为历史参考；与本文件冲突时，以本文件和以下四份专项文档为准：

- 《C3单主控系统架构与职责边界 V1.0》；
- 《ESP32-C3与CI1302通信协议 V1.0》；
- 《浴霸控制状态机与安全规则 V1.0》；
- 《东信样板硬件接口及验收要求 V1.0》。

## 1. 产品目标

交付可量产的 AI 浴霸方案。用户可通过离线语音、在线AI语音、BLE墙面触控板、BLE手持遥控器和微信小程序使用设备；东信内部后台管理产品配置、语音版本、设备、知识库、模型、日志和费用。

第一阶段优先完成 ESP32-C3 固件和真实样板，生产平台在不阻塞硬件研发的前提下持续建设。量产容量按10万台设计。

## 2. 固定架构

| 领域 | 决策 |
|---|---|
| 唯一业务主控 | ESP32-C3；取消独立STM32/传统MCU |
| 语音前端 | CI1302首选，CI1303兼容备选 |
| CI职责 | 麦克风、降噪、VAD、唤醒、离线命令、音频编解码和播放 |
| C3职责 | WiFi、BLE配网、MQTT、在线音频、控制状态机、传感器、遥控和OTA |
| 负载控制 | 所有来源先进入C3统一安全状态机，CI不得直接控制负载 |
| IO扩展 | 同一I2C总线挂载3颗PCF8574，7位地址0x20/0x21/0x22，共24路低速IO，100kHz |
| IO安全 | PCF端口低有效；C3原生GPIO控制独立LOAD_ENABLE，硬件默认禁止危险负载 |
| 本地控制 | C3内置BLE连接1个墙面触控板和1个手持遥控器，主板不增加蓝牙接收模块 |
| 音频电路 | 按CI1302官方参考设计，C3侧不重复增加ES8311 |
| CI链路 | UART0 115200bps传控制事件，I2S传16kHz/16bit/单声道PCM，CI外部晶振为必选 |
| Flash/OTA | C3量产板至少8MB，预留A/B OTA；CI固件和资源也保留升级能力 |
| 备选 | ESP32-S3保留开发测试和量产备选，不从工程删除 |

## 3. 语音和AI链路

- 产品唤醒词基线为“小东小东”；
- 同时支持分句唤醒和“小东小东打开暖风”连续说法；
- 固定命令无论联网与否都优先由CI1302处理，使用提示音反馈，不产生云端费用；
- CI离线未命中且有网时，C3上传音频到在线ASR；
- 简单文本优先规则，售后问题优先知识库，其余调用LLM；
- LLM只输出结构化结果，服务端预检后仍由C3本地安全状态机终审；
- 断网且离线未命中时播放“网络未连接，请使用固定指令”；
- 第一版半双工，播报时不接受普通语音打断；安全事件和遥控关闭仍有效；
- 唤醒词/离线命令按产品型号统一生成CI资源包并走版本发布；个人唤醒词走设备旁自学习。

## 4. 第一版能力

必须实现：照明、吹风、换气、弱暖、强暖、关闭取暖、摆风、干燥、沐浴/恒温逻辑、30至45℃目标温度、NTC、人感/雷达、BLE墙面触控板、BLE手持遥控器、BLE配网、MQTT状态与命令、在线ASR/规则/知识库/LLM/TTS。

可选待确认：夜灯、独立除雾模式、温度显示、11个触摸键、等离子净化。未装配能力在界面隐藏，并在API/设备侧返回 `UNSUPPORTED`。

第一版不做：家庭和多人共享、手机号验证码、原始音频留存、摄像头、第三方智能家居生态、ESP32本地LLM、通用离线大词汇ASR。

## 5. 安全基线

- 上电后所有负载关闭，不恢复断电前危险状态；
- 取暖开启前必须先启动风机；
- 关闭取暖后默认散热120秒，最终值由热测试冻结；
- 目标温度默认40℃；
- 取暖和干燥有最长运行时间；
- NTC故障、过温、IO失联和输出异常立即关闭危险输出；
- 软件过温阈值在NTC型号、位置和温升测试完成前保持“未冻结”；
- 温控器、保险丝、继电器/可控硅、隔离、EMC和认证由东信负责；
- 不允许把软件关断作为唯一过温保护。

## 6. 平台与设备

| 项目 | 决策 |
|---|---|
| 后台用户 | 仅东信内部员工，账号密码，可选微信扫码 |
| 消费者入口 | 微信小程序为入口之一，另有BLE墙面触控板、BLE手持遥控器和语音 |
| 登录 | 微信登录，第一版不绑定手机号 |
| 配网 | 微信小程序通过BLE写入WiFi |
| 激活绑定 | 设备联网自动注册，用户扫描机身二维码首次绑定 |
| 设备关系 | 第一版单设备单归属，不做家庭共享 |
| 消息 | 量产使用MQTT，优先评估阿里云IoT；HTTP只作AI/排障兼容 |
| 设备认证 | 每台设备独立deviceSecret |
| 数据 | RDS PostgreSQL/MySQL + Redis |
| 状态 | 变化立即上报，低频心跳保活 |
| 日志 | 只保存文本和必要元数据，默认90天，不保存原始音频 |

研发阶段继续使用本地MQTT Broker和JSON仓储。测试环境与未来生产环境必须隔离。

## 8. 历史资产说明

`backup0424`的旧STM32代码用于理解功能、步进电机和既有操作习惯，不作为新固件质量标准。

《AXENT浴霸通信协议.pdf》《东信浴霸 MCU 串口协议 V0.2》、`uart_bridge`和电脑MCU模拟器继续保留，用于旧产品兼容及协议测试。新样板没有独立MCU，云端/CI/遥控命令不再经过这条UART控制链路。

## 9. 变更规则

架构变更必须有以下至少一种证据：样板无法满足资源或实时性、稳定性测试不达标、BOM失去优势、法规/安全要求变化，或合同能力必须由其他方案实现。口头设想和未确认的可选能力不改变量产基线。

C3切换到S3、恢复独立MCU、修改CI芯片或修改危险负载保护均需形成版本化决策记录。
