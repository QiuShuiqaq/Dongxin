# 东信 AI 浴霸项目开发进度简报

**日期：2026年9月24日**  
**当前阶段：软件和开发板测试阶段，等待东信样板机**

## 一、目前进展

项目目前已经完成了第一轮软件开发和基础测试，后台、AI服务和ESP32-C3开发板之间的基本流程已经打通。现在的重点，是在东信提供样板机和语音芯片资料后，继续做真实硬件联调。

目前已经完成的主要内容如下：

1. 确定第一版采用 **ESP32-C3作为主要控制芯片**，不再另外增加传统浴霸MCU；ESP32-S3保留作为备用测试方案。
2. 确定采用 **CI1302作为离线语音芯片**，负责“小东小东”、固定语音命令、麦克风和语音播放等功能。
3. 确定使用 **3颗PCF8574扩展芯片**，为浴霸预留24路低压控制接口，后续用于灯、风机、换气、取暖、摆风、雷达、显示等功能。
4. 完成ESP32-C3固件基础功能，包括联网、后台通信（MQTT）、设备状态、命令处理、必要的安全保护和断电后的安全关闭逻辑。
5. 完成AI语音服务的基本流程：语音识别（ASR）、简单命令判断、复杂问题交给大模型（LLM）、知识库问答预留，以及生成控制结果或回复文字。
6. 完成“东信产品研发中心”和“东信设备运营平台”的基础页面。两个平台已经分开，研发测试功能不会和后续生产运营功能混在一起。
7. 已开发批量测试和结果导出功能，后续可以批量测试ASR、LLM、TTS，并保存测试结果。
8. 完成“立创板实验室”，可以通过网页读取开发板的传感器、触摸、按键、屏幕和网络状态。

## 二、已经实际测试通过的内容

### 1. ESP32-C3联网和后台通信

ESP32-C3 SuperMini开发板已经完成以下测试：

- 连接指定Wi-Fi；
- 连接本地后台的MQTT服务；
- 接收后台发送的命令；
- 执行照明、弱暖、强暖等文本模拟命令；
- 把执行结果返回后台；
- 设备重启后能够记住最近处理过的命令，避免重复执行。

这部分证明了“开发板联网—后台发送命令—设备处理—返回结果”的基本流程已经可以工作。由于目前没有东信样板和真实负载，这还不代表灯、风机或取暖器已经完成真实动作测试。

### 2. 立创ESP32-C3音频开发板

立创开发板已经烧录专用测试固件，并接入研发中心的“立创板实验室”。最近一次真实读取结果如下：

- 板载5个I²C器件全部有响应；
- 温度约29.9℃，湿度约71.1%；
- 六轴传感器可以返回姿态数据；
- 电子罗盘可以返回方向数据；
- 触摸芯片可以被识别；
- 屏幕控制功能已经接入网页；
- 功放默认关闭，避免上电或测试时突然播放声音。

该开发板主要用于验证ESP32-C3的联网、音频、传感器和网页联调能力，不能代替东信最终浴霸样板机的功能验收。

### 3. ASR、LLM、TTS服务

当前已经分别确认三项服务可以正常调用：

- ASR可以把测试音频转换成文字；
- LLM可以根据测试文字判断浴霸应该执行什么操作，并返回控制结果；
- TTS可以把文字生成语音文件。

目前只是确认服务能够正常工作，还没有使用正式测试数据统计准确率，也没有完成东信样板机上的实际播放测试。

这些内容属于研发测试版本，主要用于把流程跑通和准备后续样板联调，不是最终面向消费者的生产平台。

## 五、下一步安排

建议按下面顺序推进：

1. 先完成ASR、LLM、TTS的测试数据整理和批量测试，形成第一批测试结果；
2. 东信提供产品说明书、功能说明、故障码、安装维护和售后资料，建立第一版知识库；
3. 东信提供样板机原理图、ESP32-C3引脚表、PCF8574端口定义和主要负载参数；
4. 获取CI1302完整开发资料后，完成CI1302和ESP32-C3的通信适配；
5. 样板机到位后，先做低压接口和测试灯验证，再做语音、传感器、电机和负载测试；
6. 确认硬件动作和安全保护没有问题后，再进行连续运行、温升和联网稳定性测试；
7. 样板测试稳定后，再把后台迁移到阿里云，并开始做生产账号、设备绑定和小程序功能。

## 六、当前阶段结论

目前项目已经完成软件基础、后台基础、AI服务接口和ESP32-C3开发板联调，具备继续推进样板研发的条件。

现在最关键的不是继续增加页面，而是尽快拿到东信样板机、CI1302开发资料和正式产品资料，把以下三件事做成真实结果：

1. 浴霸主要功能能否由ESP32-C3稳定控制；
2. “小东小东”及固定离线命令能否在CI1302上稳定运行；
3. ASR、LLM、TTS和知识库在正式测试数据下能否达到项目要求。

在上述内容完成前，当前系统应定位为研发测试版本，不应作为量产固件或正式生产平台使用。
