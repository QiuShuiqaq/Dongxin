# 云端与小程序实施顺序 V1.0

日期：2026-10-26  
范围：CI1302 到货前可独立推进的合同工作。当前样机 STM32 + ESP32-C3 链路不改动。

## 1. 当前状态

| 模块 | 已有基础 | 正式联调前缺口 |
|---|---|---|
| AI 服务端 | ASR、规则、知识库、LLM、TTS及设备 API | 消费者身份边界、生产数据库、云环境配置与监控 |
| 企业后台 | 设备、知识库、AI、日志与系统页面；员工账号密码模式 | 生产账号启用、角色/审计、真实数据持久化与部署验收 |
| 微信小程序 | 状态、控制、文字问答、帮助、主动沟通设置原型 | 正式 AppID、微信登录、扫码绑定、消费者专用 API、HTTPS 域名 |
| MQTT | 本地 Broker 和样机消息闭环 | 云端接入选型、每设备独立凭证、TLS 和运行监控 |
| 数据 | 本地 JSON | RDS 表结构、迁移、备份、90 天文本日志清理 |

小程序当前仅为本地研发原型。`touristappid`、固定测试设备 ID 和本地 API 配置都不能用于正式发布。原型不得使用后台管理员令牌，也不得以员工接口代替消费者鉴权。设备联网注册和用户扫码绑定是两个不同步骤，不能把“自动注册”解释为“自动归属任意用户”。

## 2. 实施顺序

1. **接口与安全边界**：建立消费者身份、设备归属和最小数据接口；消费者只能访问自己绑定的设备。设备命令保留 `QUEUED`、`APPLIED`、`FAILED`、`TIMEOUT` 状态，`APPLIED` 仅来自设备真实回执。内部后台继续单独鉴权。
2. **持久化**：选择阿里云 RDS PostgreSQL，先迁移设备、命令、状态、用户归属、知识库和员工账号；再迁移测试记录及日志。提供迁移、备份与恢复演练，不直接把本地 JSON 放到公网作为生产数据源。
3. **小程序闭环**：微信 `wx.login` 换取服务端会话，扫码申请绑定，展示归属设备状态、常见控制、文字 AI 问答、产品帮助和主动沟通设置。控制能力依据实际样机协议开放；未装配、未验证或有安全门禁的功能不展示为可执行。
4. **测试环境部署**：在云端测试环境配置域名、HTTPS、API、运营页面、数据库、最小权限和日志；设备接入先使用当前协议适配，评估阿里云 IoT 平台后再迁移 MQTT。测试环境和正式环境隔离。
5. **联调与交付**：分别记录登录/绑定、设备状态、控制回执、问答引用、主动沟通及异常恢复测试。真实雷达/人感、CI1302 与整机声学结果留待硬件具备后填写，不提前写成通过。

## 3. 公网发布门禁

- 员工后台和消费者小程序使用不同身份与接口权限；不能以关闭鉴权换取小程序连通。
- API Key、微信 AppSecret、设备密钥不进入小程序包、前端构建物或 Git。
- 域名使用 HTTPS，并配置微信小程序合法请求域名；禁止生产包访问 `127.0.0.1` 或内网 IP。
- 后端拒绝越权设备访问、过期命令、无效参数及离线危险动作；前端不能自行宣布命令执行成功。
- 数据库有定期备份和一次可复核的恢复演练；文本日志按 90 天策略清理，不保存原始用户音频。
- 生产环境完成监控、错误告警和容量测试后，再按实际并发量扩容；不能根据样机测试推断 10 万台设备容量。

## 4. 外部前置资料

- 阿里云测试服务器的实例信息、操作系统、域名及 DNS 管理方式；正式购买和公网部署需由项目负责人确认费用与访问范围。
- 微信小程序主体与正式 AppID、开发者权限、合法请求域名配置权限。AppSecret 只通过服务器环境变量或密钥服务交接，不在聊天、文档或仓库中传递。
- 东信已确认的产品说明、功能说明、安装维护、故障码及售后规则，用于知识库发布。
- 最终控制能力和小程序可用动作清单，以样机协议和实测结果冻结。

在这些资料未齐全时，仍可先完成本地 API、数据库迁移脚本、消费者身份/绑定接口与小程序页面；不得宣称云端或小程序已正式上线。
