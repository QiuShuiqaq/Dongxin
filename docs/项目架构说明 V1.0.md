# 东信智能浴霸 AI 项目架构说明 V1.0

> 说明：仓库结构可供参考；产品硬件和执行链路以《项目执行基线 V1.1》为准。

更新日期：2026-10-20

## 1. 仓库定位

该仓库同时包含独立的产品研发中心、设备运营平台、设备接入模拟、ESP32固件和微信小程序原型。当前可在本地完成模型/规则测试、MQTT命令闭环、板卡与IO定义、固件执行追踪、CI1302语义事件模拟和成本评估；生产部署会把本地JSON与MQTT替换为阿里云RDS/Redis/IoT。

产品硬件基线保留现有STM32浴霸控制，ESP32-C3负责联网、独立在线音频和STM32协议适配，CI1302只负责唤醒及离线固定命令。在线音频由C3独立麦克风和Codec提供，首版与CI1302采用双麦克风。

## 3. 软件分层

### 共享契约

`packages/shared/src/index.ts` 是前后端协议源，包含：

- 设备意图、动作、状态、命令和事件；
- 语音链路阶段和成本；
- 产品硬件能力；
- CI1302语音配置、离线命令和发布状态；
- CI1302事件模拟；
- 板卡、管脚、总线、PCF8574端口和验证状态；
- 固件命令执行轨迹；
- 模型、评测、知识库和主动沟通。

接口新增字段应先在共享Schema定义，再进入API和页面，避免三端各自解释。

### API

```text
routes        HTTP边界和Schema解析
services      业务规则、状态流转和第三方编排
repositories  JSON数据读写；生产阶段替换RDS仓储
storage       原子JSON文件写入
```

主要服务：

| 服务 | 职责 |
|---|---|
| `hardwareConfig.service` | 产品能力、CI语音版本、状态机和CI事件模拟 |
| `deviceAccess.service` | 设备注册、状态、事件、语音和命令结果 |
| `mqttGateway.service` | 本地MQTT上下行和命令生命周期 |
| `voicePipeline.service` | ASR、离线/在线规则、知识库、LLM、安全、TTS和设备阶段 |
| `deviceRegistry.service` | 设备、命令和事件；下发前检查产品能力 |
| `productionCost.repository` | 研发/量产成本参数 |
| `console.service` | 聚合研发域和运营域的独立控制台数据 |

### 产品研发中心

`apps/development-console`只承载研发工作：

- 研发总览与Gate；
- 端到端系统拓扑；
- 开发板管脚、C3独立Codec、CI UART和STM32 UART链路；
- MQTT到HAL、状态同步和回执的固件执行链；
- C3实板命令联调；
- CI1302、规则、ASR、LLM和TTS链路；
- 版本交付门禁。

### 设备运营平台

`apps/operations-console`只承载生产运营工作，包括设备、激活绑定、告警售后、发布、AI运营、审计和基础设施。平台排除 `SIMULATOR` 设备，不提供烧录、串口、引脚或测试命令入口。当前RDS、Redis、阿里云IoT和员工认证未配置，因此页面明确标记为“阻塞上线”。

`apps/web`保留尚未迁移的模型评测和配置能力，只是过渡期研发工具，不再作为默认入口。

### 固件

当前已经完成C3 WiFi/MQTT文本模拟闭环和STM32到C3的只读状态帧接收。目标内部链路：

```text
MQTT / CI1302离线语义 / 在线AI / 定时器
  → 统一命令队列
  → C3能力与安全预检
  → STM32协议适配器
  → 现有STM32控制与安全状态机
```

现有`uart_bridge`是历史模拟协议，不用于当前STM32样机。当前使用独立的STM32协议适配器，未完成双向验证前保持C3发送禁用。

## 4. 研发数据

| 文件 | 内容 |
|---|---|
| `product-profiles.json` | 产品能力、安全默认值和历史降本方案 |
| `board-profiles.json` | 当前开发板、STM32联调接口和已退役量产候选板定义 |
| `voice-profiles.json` | 唤醒词、离线词表、语义ID、资源和状态 |
| `devices.json` | 研发设备注册信息 |
| `device-commands.json` | 命令生命周期 |
| `device-events.json` | 状态、故障和语音事件 |
| `model-providers.json` | ASR/LLM/TTS供应商和价格 |
| `test-sets.json` | 回归测试集 |
| `evaluations.json` | 模型评测结果 |
| `production-cost-settings.json` | 成本和路由假设 |

JSON只用于单机研发，不支持10万台生产并发。生产迁移时保持服务接口，替换仓储实现。

## 5. 关键边界

- CI1302离线命令只上报语义ID；
- CI1302不传PCM，C3通过独立Codec采集在线音频并播放TTS；
- LLM只输出结构化意图；
- 服务端安全校验只做预检；
- C3完成联网侧能力检查，STM32保留现有负载状态机和硬件安全控制；
- C3必须依据STM32真实状态回执确认动作结果；
- 220V和硬件保护由东信负责；
- 未装配能力返回 `UNSUPPORTED`；
- 原始音频不落库。

## 6. 本地运行

Node.js位于D盘，直接使用项目脚本：

```powershell
Set-Location D:\workspace\Dongxin
.\start-dev.ps1
```

- 产品研发中心：`http://127.0.0.1:3010`
- 设备运营平台：`http://127.0.0.1:3020`
- API：`http://127.0.0.1:3077`
- MQTT：本机 `mqtt://127.0.0.1:1883`，C3使用 `mqtt://192.168.16.146:1883`

验证：

```powershell
.\verify-dev.ps1
```

固件：

```powershell
Set-Location D:\workspace\Dongxin\firmware
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-and-flash.ps1
```

串口监视器按 `Ctrl+]` 退出。
