# ESP32-C3 与 CI1302 通信协议 V1.0

文档状态：项目逻辑基线，待 CI1302 SDK 和样板映射验证<br>
控制接口：3.3V TTL UART0，115200bps，8N1<br>
音频接口：I2S PCM，16kHz、16bit、单声道<br>
更新日期：2026-09-14

## 1. 结论与边界

CI1302 是语音前端，ESP32-C3 是唯一业务主控。

- UART0 只传唤醒、VAD、离线语义、播放控制、版本和故障等低带宽消息；
- I2S 只传双向 PCM，不在 UART 中传 Opus、MP3 或 PCM 分片；
- CI1302 不发送 GPIO/PCF8574 端口号，也不能直接控制负载；
- C3 把语义 ID 转为统一命令，再经过能力检查和本地安全状态机；
- 厂商 SDK 若已有固定消息格式，由适配层映射到本文语义，不强行替换厂商底层帧；
- 数据手册只能证明硬件能力，不能证明项目事件、音频路由和资源升级 API 已可用。

## 2. 电气基线

| 项目 | 要求 |
|---|---|
| UART 电平 | 3.3V TTL，禁止连接 5V TTL 或 RS-232 |
| UART 参数 | UART0，115200bps，8N1，无硬件流控 |
| UART 接线 | C3_TX -> CI_RX；C3_RX <- CI_TX；双方共地 |
| I2S 格式 | 16kHz、16bit、单声道，首版按标准 I2S 对齐 |
| I2S 信号 | BCLK、LRCLK/WS、CI_TO_C3_DATA、C3_TO_CI_DATA；MCLK 预留 |
| 晶振 | CI1302 必须使用外部晶振 |
| 复位/烧录 | CI_RESET、CI_BOOT/升级接口和 UART0 均提供测试点 |
| 串扰 | UART/I2S 串联电阻、走线和地参考按启英泰伦参考设计评审 |

I2S 时钟主从暂定 C3 为 Master、CI1302 为 Slave。投板前必须用 CI1302 官方 SDK 示例确认该组合；如果 SDK 只支持 CI Master，应在原理图评审时切换方向并更新引脚表，不能等投板后再猜。

CI1302 的 UART0 同时承担厂商烧录/升级。进入 CI 升级模式时，C3 必须停止项目协议发送并将相关输出置为不会干扰烧录的状态。

## 3. UART 应用帧

以下帧用于双方自研应用层。若厂商 SDK 限制帧格式，保留本文消息语义、序号、校验和幂等要求，在适配表中说明差异。

所有多字节整数使用小端序。固定头 16 字节，后接负载：

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 4 | magic | 固定 `43 49 44 58`，ASCII `CIDX` |
| 4 | 1 | version | 当前 `0x01` |
| 5 | 1 | message_type | 消息类型 |
| 6 | 1 | flags | bit0 需 ACK；bit1 为响应 |
| 7 | 1 | header_length | 固定 `0x10` |
| 8 | 2 | sequence | 每个发送方向独立递增，0 不使用 |
| 10 | 2 | payload_length | V1.0 最大 240 字节 |
| 12 | 2 | header_crc16 | 对字节 0 至 11 计算 |
| 14 | 2 | payload_crc16 | 对负载计算，空负载为 `0xFFFF` |

CRC 使用 CRC-16/CCITT-FALSE：多项式 `0x1021`、初值 `0xFFFF`、不反射、结果不异或。

## 4. UART 消息

| 值 | 名称 | 方向 | 用途 |
|---:|---|---|---|
| 0x01 | HELLO | 双向 | 协议、固件、资源和能力协商 |
| 0x02 | HEARTBEAT | 双向 | 链路保活 |
| 0x10 | WAKE | CI -> C3 | 唤醒词命中，建立语音会话 |
| 0x11 | VAD_START | CI -> C3 | 用户开始说话 |
| 0x12 | VAD_END | CI -> C3 | 用户停止说话 |
| 0x13 | OFFLINE_COMMAND | CI -> C3 | 固定命令命中，只包含语义 ID |
| 0x14 | OFFLINE_MISS | CI -> C3 | 未命中、低置信度或超时 |
| 0x20 | CAPTURE_START | C3 -> CI | 请求输出当前会话 PCM |
| 0x21 | CAPTURE_STOP | C3 -> CI | 停止输出当前会话 PCM |
| 0x30 | PLAY_START | C3 -> CI | 准备接收并播放 I2S PCM |
| 0x31 | PLAY_STOP | C3 -> CI | 停止当前动态播报 |
| 0x32 | PLAY_FINISHED | CI -> C3 | 播放完成或失败 |
| 0x33 | PLAY_PROMPT | C3 -> CI | 播放 CI 本地提示音资源 |
| 0x40 | RESOURCE_INFO | 双向 | 查询/报告固件和资源版本 |
| 0x50 | SELF_LEARN_BEGIN | C3 -> CI | 能力支持时启动设备旁自学习 |
| 0x51 | SELF_LEARN_DELETE | C3 -> CI | 删除个人唤醒词 |
| 0x52 | SELF_LEARN_RESULT | CI -> C3 | 自学习结果 |
| 0x60 | FAULT | 双向 | 模块、资源或音频链路故障 |
| 0x7E | ACK | 双向 | 确认指定序号 |
| 0x7F | NACK | 双向 | 拒绝并返回错误码 |

CI 固件/资源升级使用启英泰伦官方升级流程，不在 V1.0 自定义升级数据帧。

## 5. 关键负载

### HELLO

```text
role                 uint8   1=C3, 2=CI1302
protocol_min         uint8
protocol_max         uint8
reserved             uint8
firmware_version     char[16]
resource_version     char[16]
capability_bits      uint32
```

无共同协议版本时禁用语音链路，但 BLE、本地安全和平台控制继续工作。

### WAKE

```text
keyword_id           uint16
score                 uint16  0..1000
session_id            uint32
```

`keyword_id=1` 为产品唤醒词“小东小东”。个人自学习唤醒词的 ID 从 `0x8000` 开始。

### VAD_START / VAD_END

```text
session_id            uint32
audio_sample_index    uint32  从本次开机I2S样本计数器取值
```

样本索引用于把 UART 事件与连续 I2S PCM 对齐。WAKE、VAD、离线结果和播放事件必须携带同一个 `session_id`。

### OFFLINE_COMMAND

```text
semantic_id           uint16
confidence            uint8   0..100
reserved              uint8
session_id            uint32
```

语义 ID 由平台语音版本统一管理：

| 范围 | 用途 |
|---|---|
| 1001-1099 | 功能开关和固定模式 |
| 1100-1115 | 30 至 45℃目标温度 |
| 2000-2999 | 后续产品扩展，V1.0 不使用 |
| 0x8000-0x8FFF | 个人唤醒词，不作为控制命令 |

具体词条由平台导出，C3 与 CI 工程不得各自维护一份含义不同的手工表。

### OFFLINE_MISS

```text
session_id            uint32
reason                uint8   1=未识别, 2=低置信度, 3=超时
reserved              uint8[3]
```

有网时 C3 把当前会话提交给在线 ASR；无网时请求 CI 播放固定断网提示。

### PLAY_START

```text
session_id            uint32
sample_rate_hz        uint16  固定16000
bits_per_sample       uint8   固定16
channels              uint8   固定1
expected_samples      uint32  未知时为0
```

### PLAY_PROMPT

```text
prompt_id             uint16
session_id            uint32
```

确认、拒绝、断网和忙碌提示优先使用 CI 本地资源，避免调用 TTS。

### ACK / NACK

```text
acked_sequence        uint16
status_or_error       uint16
```

错误码至少包含：`BAD_CRC`、`BAD_LENGTH`、`UNSUPPORTED_VERSION`、`UNSUPPORTED_MESSAGE`、`INVALID_STATE`、`UNKNOWN_SEMANTIC_ID`、`BUSY`、`RESOURCE_MISMATCH`、`INTERNAL_ERROR`。

## 6. I2S PCM 会话

- CI -> C3：麦克风前端输出，是否为降噪后 PCM 必须由 SDK 和录音对比确认；
- C3 -> CI：C3 输出的动态 TTS PCM，经 CI DAC/功放/扬声器播放；
- 首版半双工，播放期间不启动普通录音会话；
- UART 事件定义会话边界，I2S 不再封装项目私有帧；
- C3 使用小块 DMA 和环形缓冲，禁止把整段语音一次性放入 RAM；
- 首版先用 PCM 打通，网络侧压缩格式在 C3 性能和并发压力测试后决定。

为保证离线未命中后在线 ASR 不丢失句首，推荐流程是：唤醒后 C3 接收 PCM 并流式发送到服务端临时会话，服务端暂不调用 ASR；收到 `OFFLINE_COMMAND` 后丢弃，收到 `OFFLINE_MISS` 后才提交 ASR。这样固定命令仍不产生 ASR/LLM/TTS费用，同时避免在 C3 RAM 中保存整句。

## 7. 可靠性

- HELLO、WAKE、VAD_END、OFFLINE_COMMAND、OFFLINE_MISS、播放开始/结束必须 ACK；
- ACK 超时 100ms，最多重试 2 次；相同 sequence 只执行业务一次；
- HEARTBEAT 每 5 秒一次，连续 3 次缺失判定链路离线；
- CRC、长度或未知消息错误不得改变设备状态；
- 控制事件队列优先于音频搬运，故障和关闭命令不能被 PCM 阻塞；
- CI 重启、C3 重启、UART 拔插后必须重新 HELLO 和 RESOURCE_INFO；
- 资源版本不一致时禁用离线语义控制，防止同一 ID 含义不同；
- CI 故障不影响 BLE 控制、MQTT 控制和 C3 本地安全。

## 8. 启动与离线命令时序

```text
C3/CI上电
  -> 各自保持安全输出
  -> UART HELLO/ACK
  -> RESOURCE_INFO比对
  -> I2S参数就绪
  -> READY
```

```text
CI1302              ESP32-C3              统一控制器
  | WAKE(session)      |                       |
  |------------------->|                       |
  | OFFLINE_COMMAND    |                       |
  |------------------->| 语义/能力/安全校验    |
  |                    |---------------------->|
  |                    |<---执行或拒绝----------|
  |<--ACK或NACK--------|                       |
  |<--PLAY_PROMPT------|                       |
```

ACK 只表示事件已被可靠接收；最终执行结果由 C3 安全状态机决定。

## 9. 样板验收

1. 双方握手、资源版本一致后进入 READY；
2. 错 CRC、超长帧、未知消息和重复帧均不造成重复动作；
3. “小东小东”分句和连续说法均能建立正确会话；
4. 离线语义映射到 C3 统一命令，CI 无负载控制输出；
5. 未启用能力返回拒绝提示；
6. 断网未命中播放本地断网提示；
7. 联网未命中提交完整 PCM，ASR 不丢句首；
8. 动态 PCM 能完整播放，播报期间保持半双工；
9. WiFi/MQTT 与 I2S 并发时无持续丢帧、内存下降或异常复位；
10. UART 拔线、CI/C3 单独重启后自动恢复；
11. 连续 8 小时语音和联网压力测试通过；
12. CI 官方升级流程失败时可恢复到可用版本。

## 10. SDK 到件后的必做映射

东信或启英泰伦需提供 SDK、资源生成工具、烧录工具和示例工程。软件侧据此形成“厂商 API/消息 <-> 本协议语义”表，并实测：

- UART0 是否允许应用协议与升级复用；
- I2S 主从、MCLK需求、采样对齐和双向能力；
- 输出 PCM 是否经过实际启用的降噪链；
- 播放 PCM 是否能进入 CI DAC；
- 唤醒、VAD、离线命中、未命中和播放完成事件；
- 连续唤醒命令和设备旁自学习能力；
- 固件/资源版本读取和官方恢复流程。

任一能力未由 SDK 或样板证明时，平台应显示“待验证”，不得标成量产完成。
