# 研发中心与设备运营平台使用说明 V1.0

更新日期：2026-09-14

## 1. 目标

研发和生产运营使用两个独立前端，避免固件调试、串口、引脚和模拟数据进入真实设备运营流程。两个前端可独立构建和部署，当前共享Fastify API，后续生产部署继续按研发域和运营域隔离权限。

| 平台 | 使用人员 | 本地入口 | 允许的工作 |
|---|---|---|---|
| 产品研发中心 | 固件、硬件、AI、测试人员 | `http://127.0.0.1:3010` | 板卡定义、执行链、实板联调、语音和交付Gate |
| 设备运营平台 | 东信内部运营、售后、发布人员 | `http://127.0.0.1:3020` | 生产设备、绑定、告警、发布、审计和基础设施 |

## 2. 研发中心使用顺序

1. 在“研发总览”确认当前Gate和阻塞项。
2. 在“系统拓扑”确认C3、CI1302、PCF8574、传感器、本地控制和云端的职责边界。
3. 在“引脚与IO”选择实际板卡，核对C3管脚、总线和3颗PCF8574的24路端口。`TBD/PLANNED`不得当作已确认原理图。
4. 在“固件执行链”检查命令是否依次经过MQTT、解析、队列、安全状态机、Controller、HAL、状态同步和结果回执。
5. 在“实板联调”对当前设备下发命令。`LOCAL_VIRTUAL`只证明真实C3内部软件闭环，不证明继电器、电机或220V负载已通过。
6. 在“AI与语音”核对离线优先、在线降级和成本路由。
7. 在“版本交付”逐项关闭Gate，未完成低压IO、CI1302和真实负载验收时不得进入生产发布。

## 3. 运营平台边界

运营平台只显示非 `SIMULATOR` 设备，不显示串口、烧录、引脚和研发命令模拟。第一版采用单设备归属，不实现家庭与多人共享。

当前页面中的“预生产环境”和“阻塞上线”是有效门禁，不是装饰状态。满足以下条件前不得面向真实消费者设备：

- 东信内部员工账号密码认证和可选微信扫码；
- 阿里云IoT每台设备独立 `deviceSecret` 及完整生命周期；
- RDS PostgreSQL、Redis、备份恢复和数据迁移；
- 告警通知、操作审计、监控指标和发布审批；
- 文本日志90天清理策略，不保存原始音频。

## 4. 本地启动与验证

```powershell
Set-Location D:\workspace\Dongxin
.\start-dev.ps1
```

启动后同时提供MQTT `1883`、API `3077`、研发中心 `3010` 和运营平台 `3020`。

```powershell
npm.cmd run typecheck
npm.cmd run build
npm.cmd run verify:consoles
```

浏览器验收遍历两个平台的全部桌面和390px手机页面，检查控制台错误、全局横向溢出、24路PCF8574定义、运营设备隔离以及 `LOCAL_VIRTUAL` C3命令闭环。自动命令测试在结束时执行“整机待机”，物理HAL模式不会自动下发控制命令。

## 5. 独立构建

```powershell
npm.cmd run build -w @dongxin/development-console
npm.cmd run build -w @dongxin/operations-console
```

构建产物分别位于 `apps/development-console/dist` 和 `apps/operations-console/dist`。生产环境应使用不同域名或路径、不同角色权限和独立访问审计；不能仅依靠前端隐藏菜单实现权限隔离。

## 6. 数据真实性规则

- SuperMini定义只代表当前开发验证板，不是量产管脚基线。
- DX-AI-01 Rev.A未确认的GPIO保持 `TBD/PLANNED`。
- PCF8574端口矩阵是软件接口规划，最终电气原理图由东信硬件工程师确认。
- 固件中间阶段目前由命令生命周期重建；动作结果来自C3回执，后续接入逐阶段Trace事件。
- 运营指标只统计运营设备池，研发模拟器不能计入设备总数和在线率。
