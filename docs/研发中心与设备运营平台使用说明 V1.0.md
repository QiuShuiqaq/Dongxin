# 研发中心与设备运营平台使用说明 V1.0

更新日期：2026-10-20

## 1. 平台边界

| 平台 | 使用对象 | 本地入口 | 后续处理 |
|---|---|---|---|
| 东信产品研发中心 | 本项目软件研发和测试人员 | `http://127.0.0.1:3010` | 仅作为本地研发工具，不交付生产部署 |
| 东信设备运营平台 | 东信内部运营和售后人员 | `http://127.0.0.1:3020` | 购买云服务器后完成生产化并部署 |

两套前端当前共享本地API，但业务边界已经分开。服务端已提供可配置的员工登录门禁；本地研发默认免登录，正式部署必须启用认证并继续补齐角色权限和登录审计。

## 2. 产品研发中心

研发中心只保留当前能够直接支持开发和形成测试证据的六个入口：

| 页面 | 用途 |
|---|---|
| 研发总览 | 查看 STM32 + C3 + 后续CI1302基线、当前Gate和限制 |
| 样机联调 | 实时查看STM32收发帧、解析状态和命令回执；按固件阶段开放控制 |
| 固件与烧录 | 调用本机代理完成构建、烧录和串口监视 |
| AI服务配置 | 配置和诊断ASR、LLM、TTS服务 |
| 在线语音 | 单测ASR/LLM/TTS并执行受控整链路测试 |
| 批量测试与报告 | 管理数据集、批量执行、复查和导出结果 |

当前立创板采用STM32串口分级适配。GPIO19接收和GPIO18发送已接通，照明、吹风已完成真实动作和匹配回执闭环。研发中心每秒读取一次协议记录；只有STM32返回命令和值匹配且状态一致的32字节回执，平台才把命令记录为成功。其他负载尚未留存验证记录，恒温继续由固件硬门禁禁用，不能只通过前端绕过。

音频测试必须由人工点击。浏览器或开发板播放不得在页面加载、自动刷新、设备上线或批量任务中自动触发。

### 2.1 立创板录音归档与ASR批测

CI1302未到期间，可以用立创ESP32-C3音频板建立在线ASR工程数据集：

1. 在“批量测试与报告”创建或选择ASR测试集；
2. 填写本条录音的期望文字；
3. 点击“从立创板采集”；
4. 页面显示“正在录音”后，在开发板麦克风前说出期望文字；
5. 设备静音采集6秒PCM，服务器封装为WAV并自动归档到所选测试集；
6. 先采集5条预检，确认录音和文本无误，再继续建立完整数据集；
7. 数据集完成后选择ASR服务并启动批量任务，导出CSV、JSON和HTML结果。

采集过程中功放保持关闭，不播放“我在”或其他提示音，也不向STM32下发控制。页面提供“停止采集”按钮；进入服务器识别阶段后，原始录音已经上传，停止按钮不再取消该次处理。

该流程可验证立创板麦克风、ES8311、I2S、PCM上传和在线ASR，不形成CI1302唤醒率、离线命令准确率或量产浴室声学结论。

## 3. 设备运营平台

运营平台只保留后续生产运行需要的内容：

| 页面 | 用途 |
|---|---|
| 运营总览 | 查看设备在线、告警、命令成功率和核心服务状态 |
| 设备管理 | 查询设备档案、状态、固件和最近通信 |
| 告警与日志 | 查询设备故障、控制结果和系统记录 |
| 知识库 | 录入产品说明、安装维护、故障码和售后规则 |
| AI运营 | 查看已批准的线上模型并管理主动沟通策略 |
| 系统状态 | 查看MQTT、数据库、鉴权和部署门禁 |

运营平台不包含串口、烧录、引脚、开发板实验、模型密钥修改或研发模拟器。第一版按单设备归属处理，不实现家庭和多人共享。

### 3.1 员工登录门禁

本地开发保持 `OPS_AUTH_MODE=disabled`。正式服务器必须改为 `enabled`，并同时配置：

| 环境变量 | 用途 |
|---|---|
| `OPS_ADMIN_USERNAME` | 首个内部管理员账号 |
| `OPS_ADMIN_DISPLAY_NAME` | 页面显示名称 |
| `OPS_ADMIN_PASSWORD_HASH` | PBKDF2密码摘要，不保存明文密码 |
| `OPS_AUTH_TOKEN_SECRET` | 会话签名密钥，至少32个随机字符 |
| `OPS_CORS_ORIGINS` | 允许访问API的正式运营平台域名，多个域名用逗号分隔 |

密码摘要在项目根目录执行 `npm.cmd run auth:hash` 生成，命令行会隐藏输入。摘要和签名密钥只写入服务器环境变量或密钥服务，不提交Git。登录会话默认8小时，保存在浏览器会话存储中，关闭浏览器后失效。

启用认证后，除健康检查、登录和设备接入接口外，管理API均要求有效员工会话。当前第一版只有管理员角色，细分运营、售后和只读权限属于正式上线前工作，不得把单管理员实现描述为完整权限系统。

### 3.2 设备身份边界

仓库内置MQTT Broker只用于本地研发。开发板当前使用互不相同的研发密钥，Broker会校验`clientId`、用户名、密钥和设备专属Topic；这些测试密钥不得进入量产。

量产优先采用阿里云IoT设备身份。每台设备在生产烧录或激活工序取得独立`deviceSecret`，平台只保存设备身份、状态和生命周期信息，不在源码、固件公共模板或Git中保存整批明文密钥。若评审后仍部署仓库内置Broker，必须设置`MQTT_BROKER_MODE=production`并显式提供设备凭据；缺少凭据或继续使用默认网关密码时，Broker会拒绝启动。

## 4. 本地启动

```powershell
Set-Location D:\workspace\Dongxin
.\start-dev.ps1
```

本地端口：

- MQTT：`1883`
- API：`3077`
- 产品研发中心：`3010`
- 设备运营平台：`3020`

验证命令：

```powershell
npm.cmd run typecheck
npm.cmd run build -w @dongxin/api
npm.cmd run build -w @dongxin/development-console
npm.cmd run build -w @dongxin/operations-console
npm.cmd run verify:consoles
```

浏览器自动验收仅检查导航、请求、运行错误、横向溢出、研发/运营设备隔离和分级控制状态，不下发样机命令、不启动烧录、不播放音频。

## 5. 生产上线门禁

运营平台部署到云服务器前至少完成：

- 员工登录基础已完成；上线前补齐多账号、角色权限、登录失败限制和审计；
- HTTPS、域名和密钥托管；
- 阿里云IoT或经评审的MQTT集群，每台设备独立 `deviceSecret`；
- RDS PostgreSQL或MySQL、Redis、备份恢复和数据迁移；
- 设备自动注册、合法激活和生命周期管理；
- 服务监控、告警通知、操作审计和故障追踪；
- 文本日志默认90天清理，不保存生产原始音频。

当前页面显示“部署准备阶段”属于有效状态，不代表已经满足生产上线条件。
