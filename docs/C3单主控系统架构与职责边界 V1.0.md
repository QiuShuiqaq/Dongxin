# C3 单主控系统架构与职责边界 V1.0

文档状态：研发基线
适用产品：东信 AI 浴霸第一版
主控方案：ESP32-C3 + CI1302 + 3 × PCF8574
更新日期：2026-09-14

## 1. 结论

第一版取消独立 STM32/传统 MCU，由 ESP32-C3 作为唯一业务主控。ESP32-C3 负责联网、设备控制和安全状态机；CI1302 仅负责语音前端和音频输入输出，不允许绕过 C3 直接驱动任何负载。

该方案可以实现已确认的产品能力。C3 引脚数量通过三颗PCF8574提供的24位低速IO和合理的原生引脚分工解决；是否能量产不以“代码能跑”为判断标准，必须通过样板温升、异常关断、长稳和 EMC 测试。

ESP32-S3 保留为研发验证及备选，不作为当前量产首选，也不从工程中删除。

## 2. 总体链路

```text
麦克风/扬声器
      │
      ▼
   CI1302 ── UART控制 + I2S PCM音频 ── ESP32-C3
   │  │                               │
   │  ├─ 唤醒/VAD/离线命令语义        ├─ WiFi/BLE/MQTT
   │  ├─ 16kHz PCM采集                ├─ 统一命令队列
   │  └─ 16kHz PCM播放                ├─ 安全状态机
   │                                  ├─ ADC/NTC
   │                                  ├─ 内置BLE墙面板/遥控器
   │                                  └─ I2C/3 × PCF8574
   │                                              │
   └──────────────────────────────────────────────┴─ 低压驱动接口
                                                    │
                                  照明/风机/换气/PTC/摆风等
```

在线链路：

```text
CI1302 未命中离线命令
  → CI1302 通过 I2S 向 C3 输出 PCM
  → C3 经 MQTT/专用音频通道上传
  → 服务端 ASR
  → 规则匹配，未命中再调用 LLM
  → 统一结构化结果
  → 服务端安全预检
  → C3 本地安全状态机终审
  → 执行设备动作或把 TTS 音频交给 CI1302 播放
```

## 3. 芯片职责

### 3.1 ESP32-C3

- 设备唯一业务主控和最终动作裁决者；
- BLE 配网、WiFi、MQTT、设备身份认证和状态上报；
- 接收 CI1302、BLE墙面触控板、BLE手持遥控器、平台和定时器的命令；
- 统一命令排队、去重、超时、优先级和安全校验；
- 控制照明、风机、换气、弱暖、强暖、摆风等低压逻辑输出；
- 采集 NTC 和人感/雷达状态；
- 实现目标温度、散热延时、最长运行时间、故障锁定和干燥模式；
- 预留 A/B OTA 分区，量产板 Flash 不低于 8MB；
- 记录故障原因、复位原因、控制来源和关键运行状态。

### 3.2 CI1302

- 麦克风采集、前端降噪、VAD、唤醒和固定命令离线识别；
- 以语义 ID 向 C3 上报离线识别结果；
- 通过I2S向C3输出16kHz、16bit、单声道PCM，具体是否为降噪后音频由SDK验证；
- 通过I2S接收C3转发的PCM并由内部DAC播放；
- 提供提示音、模块状态、故障和资源版本信息；
- 在官方SDK和样板确认能力后支持设备旁自学习个人唤醒词；
- 支持 CI 固件/资源包升级。

CI1302 不负责：继电器/PTC/电机控制、模式互锁、温控、云端业务、最终安全判断。

### 3.3 PCF8574 × 3

- 三颗芯片并联在同一SDA/SCL总线，地址固定为0x20、0x21、0x22，共24路；
- U1承担核心负载，U2承担摆风及扩展输出，U3承担传感器和故障输入；
- PCF8574没有RESET和方向寄存器，上电端口默认为高，所有输出必须按低有效设计；
- C3原生GPIO必须管理独立LOAD_ENABLE，且外围电路在C3复位时默认禁止所有危险驱动；
- 输入位在软件影子寄存器中始终写1，输出由唯一控制任务按整字节更新。

PCF8574只输出低压逻辑，不能直接驱动继电器线圈、PTC或220V负载，也不能用于PWM、串口、NTC模拟采样或精确定时输入。

## 4. 引脚预算原则

具体 GPIO 编号必须在东信提供原理图后冻结，当前只冻结接口资源：

| 接口 | C3 原生资源 | 说明 |
|---|---:|---|
| CI1302 UART | 2 GPIO | UART0，3.3V，115200bps，控制事件及升级 |
| CI1302 I2S | 5 GPIO | MCLK/SCLK/LRCLK/SDI/SDO，16kHz PCM；SDK验证前全部预留 |
| PCF8574 I2C | 2 GPIO | SDA/SCL，100kHz，地址0x20/0x21/0x22 |
| 驱动总使能 | 1 GPIO | C3原生GPIO，硬件默认关闭，不能放到PCF自身 |
| NTC | 1 ADC GPIO | 与 WiFi 工作同时进行抗干扰实测 |
| 本地遥控 | 0 GPIO | 使用C3内置BLE，主板不增加接收模块 |
| 雷达/人感 | PCF输入或原生UART | 首版优先数字存在信号，降低原生GPIO占用 |
| 调试/量产烧录 | USB Serial/JTAG 或 UART | 测试点必须保留 |

显示、触摸键、夜灯和净化当前属于可选能力。未确认装配前不得占用量产必需的原生 GPIO，也不得在平台对设备开放控制。

若摆叶电机实测证明无法通过 IO 扩展器稳定驱动，再将其四相输出迁移到 C3 原生 GPIO或增加专用电机驱动接口，不因此恢复独立 MCU。

## 5. 命令来源和优先级

所有来源统一转成同一种内部命令，不允许分别操作 GPIO：

| 优先级 | 来源 | 处理原则 |
|---:|---|---|
| 1 | 过温、NTC故障、硬件故障 | 立即关断取暖并进入故障锁定 |
| 2 | BLE墙面板/遥控器关闭、待机 | 允许中止普通模式；散热规则仍生效 |
| 3 | CI1302 离线固定命令 | 本地低延迟执行，不调用 ASR/LLM |
| 4 | 平台/小程序 MQTT 命令 | 校验设备能力、时效和幂等 ID 后执行 |
| 5 | 在线 AI 控制结果 | 服务端预检后仍需 C3 本地终审 |
| 6 | 主动服务和定时动作 | 用户操作或更高优先级事件可中止 |

## 6. 语音工作模式

- 唤醒词基线：“小东小东”；
- 同时支持“先唤醒再说命令”和“小东小东打开暖风”连续说法；
- 固定命令无论联网与否都优先由 CI1302 识别；
- 离线未命中且联网时进入在线 ASR；
- 离线未命中且断网时播放“网络未连接，请使用固定指令”；
- 离线动作只播放提示音，减少 TTS 成本；
- 第一版半双工，播放期间不接受打断；
- 产品统一唤醒词和命令通过 CI 资源包版本发布；个人唤醒词只做设备旁自学习；
- 后台修改文本不会直接改变 CI 离线模型，必须生成资源包、样机验证、审核并发布。

## 7. 产品能力基线

已启用：照明、吹风、换气、弱暖、强暖、摆风、干燥、沐浴模式、恒温、目标温度、NTC、雷达/人感、BLE墙面触控板和BLE手持遥控器。

可选待确认：夜灯、除雾独立模式、温度显示、11 个触摸键、等离子净化。

目标温度为 30 至 45℃，默认 40℃。上电后所有负载关闭。软件过温阈值不能在没有 NTC 型号、安装位置和热测试数据时写死；硬件温控器和保险丝为强制要求。

## 8. 存储与成本原则

- 设备端不长期保存原始音频；服务器只保存识别文本和必要诊断元数据，默认 90 天；
- 固定命令不调用云端 ASR、LLM、TTS；
- 简单在线命令先走规则，不命中再调用 LLM；
- 固定提示语优先缓存音频；
- 首版CI与C3采用I2S PCM；云端仅在SDK和压力测试通过后再引入Opus/MP3优化；
- MQTT 是量产主链路，HTTP 仅作研发排障兼容；
- 生产优先评估阿里云 IoT，数据库采用 RDS PostgreSQL/MySQL，缓存采用 Redis。

## 9. 不能由软件代替的职责

以下事项由东信硬件团队负责并签字确认：220V 电气安全、隔离和爬电距离、继电器/可控硅/驱动选型、PTC和风机额定参数、温控器、保险丝、接地、EMC、安规和认证。

软件定义控制逻辑和失效要求，但不能把 C3 的软件关断当成唯一安全保护。

## 10. 待样板实测冻结项

- NTC 型号、B值、分压和安装位置；
- 软件过温阈值及回差；
- 风机/换气是否共用电机绕组及切换死区；
- 摆叶电机型号、相序、步进节拍和归零方式；
- 墙面触控板和手持遥控器的BLE芯片、按键码和配对参数；
- 雷达接口；
- 干燥模式热功率和节拍；
- CI1302实际UART SDK消息映射、I2S降噪后PCM路由和长时间音频流稳定性；
- 显示、触摸键、夜灯和净化是否装配。

这些项目未冻结不阻止软件框架开发，但阻止 220V 负载量产验收。
