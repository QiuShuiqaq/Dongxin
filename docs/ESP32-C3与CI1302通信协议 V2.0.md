# ESP32-C3与CI1302通信协议 V2.0

> 历史接口草案，2026-10-28 起不再用于当前样机接线。CI1302 改接 STM32，C3 继续使用原有 STM32 UART。新事件的语义边界见 [CI1302经STM32接入与在线离线协同 V1.0](CI1302经STM32接入与在线离线协同%20V1.0.md)。本文不代表已实现或已验证的 CI1302 厂商串口协议。

| 项目 | 内容 |
|---|---|
| 文档编号 | DX-RD-IF-CI-002 |
| 文档状态 | 历史逻辑草案，当前拓扑已被替代 |
| 控制接口 | 3.3V TTL UART，建议115200bps、8N1 |
| 音频接口 | 无；在线音频使用C3独立Codec |
| 更新日期 | 2026-10-20 |

## 1. 范围与原则

CI1302只向ESP32-C3提供唤醒、固定命令语义和模块状态，不传输PCM或任意自然语言文本。

- CI1302不直接连接STM32控制口或负载驱动；
- 离线识别结果必须先进入C3统一命令及安全校验；
- 在线录音、本地提示和动态TTS由C3独立音频Codec承担；
- 线上的实际字节格式优先服从启英泰伦官方固件和资源工具；
- C3使用适配层把厂商码映射为本文逻辑事件，不要求为本项目重写CI底层协议；
- 数据手册中的I2S能力不属于本协议，也不作为首版验收项。

## 2. 电气要求

| 项目 | 要求 |
|---|---|
| 电平 | 3.3V TTL，禁止直接连接5V TTL或RS-232 |
| CI到C3 | `CI_TX -> C3_RX`必选 |
| C3到CI | `C3_TX -> CI_RX`建议保留 |
| 串口参数 | 首选115200bps、8N1、无硬件流控；最终以官方工程为准 |
| 公共参考 | 双方必须共地 |
| 上电默认 | TX保持空闲高，不得因上电毛刺形成有效控制命令 |
| 维护 | CI的BOOT、RESET、烧录UART和日志测试点必须保留 |
| 隔离 | CI烧录时C3 TX不得干扰厂商工具，使用串联电阻、跳线或硬件隔离 |

不再为CI1302分配到C3的I2S BCLK、WS、DIN、DOUT或MCLK。C3到独立Codec的I2S属于另一条板级接口。

## 3. 逻辑事件

| 事件 | 方向 | 必选 | 用途 |
|---|---|---:|---|
| `READY` | CI -> C3 | 建议 | CI资源加载完成，可以识别 |
| `WAKE` | CI -> C3 | 是 | “小东小东”命中，C3建立会话 |
| `OFFLINE_COMMAND` | CI -> C3 | 是 | 固定命令命中，携带语义ID |
| `VAD_START` | CI -> C3 | 否 | CI检测到说话开始 |
| `VAD_END` | CI -> C3 | 否 | CI检测到说话结束 |
| `OFFLINE_MISS` | CI -> C3 | 否 | 未识别、低置信度或超时 |
| `FAULT` | CI -> C3 | 建议 | 资源或识别模块异常 |
| `RESOURCE_INFO` | CI -> C3 | 建议 | 固件和离线资源版本 |
| `PING/QUERY` | C3 -> CI | 否 | 厂商协议支持时用于诊断 |

CI固件如果只支持固定输出码，至少必须提供`WAKE`和`OFFLINE_COMMAND`。`READY`缺失时由C3按CI官方启动时序管理就绪状态；`VAD`或`OFFLINE_MISS`缺失时，由C3独立麦克风的会话计时和服务端端点检测补偿。

## 4. 统一事件模型

C3适配层对上层输出统一结构，不把厂商字节码扩散到业务代码：

```text
event_type            READY / WAKE / OFFLINE_COMMAND / VAD_* / MISS / FAULT
vendor_code           厂商原始命令码
semantic_id           项目统一语义ID；非命令事件为0
confidence            厂商提供时填写，否则标记不可用
received_at_ms        C3单调时钟接收时间
resource_version      可读取时填写
```

厂商协议、波特率或输出码变化时，只修改CI适配层和版本映射，不修改设备控制、STM32协议或服务端意图定义。

## 5. 语义ID

| 范围 | 用途 |
|---|---|
| `1001-1099` | 照明、吹风、换气、取暖、摆风、干燥和关闭等固定功能 |
| `1100-1115` | 30至45摄氏度目标温度 |
| `2000-2999` | 后续经过评审的产品扩展 |

同义表达可以映射到同一个语义ID。C3只识别统一语义ID，不依赖CI内部使用的词条序号。

资源发布必须同时保存：

- 唤醒词及离线命令清单；
- 厂商命令码到统一语义ID的映射；
- CI固件版本、资源版本及文件SHA-256；
- 对应C3固件版本和产品型号；
- 样板测试记录。

后台修改唤醒词或离线命令只生成候选配置。必须通过启英泰伦资源工具生成并验证新的CI资源包后才能发布，不等同于在线文字配置立即生效。

## 6. C3处理规则

### 6.1 唤醒

收到`WAKE`后：

1. 如果C3正在播放TTS或本地提示，忽略本次事件，防止扬声器回声误唤醒；
2. 建立新的语音会话；
3. 从C3独立Codec的短时环形缓冲取得预录音频；该缓冲只驻留RAM，唤醒前不上传、不落盘；
4. 判断用户是否继续说话；
5. 分句唤醒时播放本地“我在”，连续说话时不插入提示；
6. 等待离线命令命中，或转入在线ASR。

### 6.2 离线命令

收到`OFFLINE_COMMAND`后：

1. 校验资源版本和语义ID；
2. 取消并删除当前临时在线音频会话；
3. 把语义ID转换成C3统一命令；
4. 执行能力检查、安全规则和重复保护；
5. 通过STM32协议下发；
6. 以STM32真实状态回执判断成功或失败；
7. 播放本地提示音，不调用云端ASR、LLM或TTS。

UART接收成功不代表设备动作成功。只有STM32回传预期状态后才能报告执行成功。

### 6.3 未命中与超时

- 有网络：C3把独立Codec采集的当前会话提交在线ASR；
- 无网络：C3播放本地“网络未连接，请使用固定指令”；
- CI不提供`OFFLINE_MISS`时，C3使用可配置会话超时；
- 超时参数必须通过分句、连续句和浴室噪声测试冻结，不在协议中写死。

## 7. 重复、异常和恢复

- 串口拆包必须检查厂商协议提供的帧头、长度和校验；
- 无校验的固定码协议必须使用明确帧边界，并在样板上执行噪声和断线测试；
- 相同命令的短时间重复帧不得造成重复动作，保护时间由实测冻结；
- 控制层仍必须保持幂等，不能只依赖串口去重；
- 未知码、非法语义ID和资源版本不一致不得改变设备状态；
- CI故障或掉线不影响C3在线控制、MQTT、STM32安全和其他本地控制；
- CI或C3重启后应重新进入`READY`流程，未就绪前不接收离线控制；
- 播放期间丢弃CI业务事件，播放结束后恢复待唤醒状态。

## 8. 最小映射表

取得CI1302 SDK、资源工程或样板后，必须形成以下可追溯表格：

| 厂商资源词条 | 厂商输出码 | 项目逻辑事件 | 统一语义ID | 参数 | 测试状态 |
|---|---:|---|---:|---|---|
| 小东小东 | 待填 | `WAKE` | 0 | 无 | 待验证 |
| 打开照明 | 待填 | `OFFLINE_COMMAND` | 待冻结 | 无 | 待验证 |
| 关闭照明 | 待填 | `OFFLINE_COMMAND` | 待冻结 | 无 | 待验证 |

未取得厂商证据的事件不得标记为“支持”。如果CI只能输出命令码而不能输出置信度、VAD、未命中或版本信息，适配层应明确记录为“不支持”，不得伪造字段。

## 9. 验收项目

1. CI上电后只在资源就绪时进入可用状态；
2. “小东小东”分句唤醒和连续句分别完成实测；
3. 每个离线词条及同义说法映射到唯一正确语义ID；
4. 未知码、截断帧、重复帧和串口噪声不产生误动作；
5. 联网固定命令不调用在线ASR/LLM/TTS；
6. 断网固定命令仍可经C3和STM32执行；
7. 断网非固定命令播放本地提示；
8. 离线未命中后，C3独立音频转在线ASR且不丢命令句首；
9. TTS播放期间不因扬声器回声产生误动作；
10. CI拔线、复位和故障不影响STM32安全控制及其他控制入口；
11. 资源版本与C3映射不一致时拒绝离线命令；
12. 连续运行和整机浴室噪声测试通过后，才能冻结量产参数。
