# 云端数据库迁移与试点准备 V0.1

更新日期：2026-10-31  
状态：数据库结构和迁移器已编写；语音文本历史可选切至 PostgreSQL；尚未连接或创建阿里云 RDS，其他核心业务仓储尚未切换

## 范围

首发数据库采用杭州地域 RDS PostgreSQL，和单台 ECS 置于同一 VPC。当前迁移覆盖设备与独立凭据、最新状态与控制版本、命令回执、设备事件、纯文本会话、知识文档及版本、主动沟通设置、员工与审计、消费者单设备归属。原始音频不入库。设备心跳只应更新 `last_seen_at` 和必要的在线态，不应每次追加 90 天历史事件。

迁移文件：`apps/api/migrations/001_core.sql`、`002_local_event_identity.sql`、`003_command_access_indexes.sql`。第二条迁移给设备事件增加按 `(device_id,event_id)` 唯一的索引；第三条为按设备查看命令历史和有界待下发查询建立索引。迁移器在一个事务中取得 PostgreSQL advisory lock，校验已执行版本的 SHA-256，并拒绝版本漂移或未知版本；不在 API 启动时自动运行。启用 PostgreSQL 设备凭据或语音历史时，API 就绪前只读核对全部迁移版本及校验和；缺失或漂移将拒绝启动。索引创建需要维护窗口和备份，数据库只建在阿里云 RDS，不要求本机安装 PostgreSQL。

设备、命令和最新状态已有独立 PostgreSQL 仓储及无数据库单元测试，包含设备分页、心跳更新时间、按设备查询待执行命令及过期过滤、命令回执行锁与终态幂等、状态部分更新与控制版本同事务递增。运营设备/命令指标已有 SQL 聚合查询，在线数按最近 35 分钟心跳计算，命令成功率按最近 24 小时计算，待确认命令不计入已完成命令。当前 JSON 回执也已改为原子终态转换；两套仓储都拒绝待确认命令的设备执行回执。

本地控制事件的 PostgreSQL 事务仓储已补齐：同一设备先锁状态行，按事件编号查重；新事件在同一事务内写状态、递增一次控制版本并存事件；重复事件复用首次版本，同编号不同内容返回冲突；任一写入失败回滚整笔事务。当前业务入口尚未启用该仓储，不能把仓储测试当作跨重启幂等验收。

设备注册的 PostgreSQL 事务仅接受已灌装且型号一致的档案，保留后台名称；首次上线或离线恢复才在同一事务内记录注册事件。首份状态上报要求 C3 提供完整开关、温度、占用和故障快照，服务端不用自造温度初始化；后续允许部分状态更新。状态、在线时间和变化事件同事务写入，环境读数变化只记事件，负载、目标温度或故障变化才推进控制版本。在线命令的首次有效回执也可在同一事务提交命令终态、状态与唯一事件，重复或冲突回执不会再次改变状态。这些数据库仓储尚未接入运行中的设备入口，需与语音控制版本及命令路径一起切换。完整字段只证明报文结构满足初始化要求；C3 上电初值可能为 `0`，温度传感器有效性仍须整机实测确认。

普通设备事件的 PostgreSQL 仓储支持按 `(device_id,event_id)` 去重：相同内容重复上报返回首次记录，同编号内容变化返回冲突且不覆盖原事件。事件载荷限制为 8 KiB，并拒绝原始音频字段；按设备读取采用最多 100 条的游标分页。命令历史也采用按设备的有界游标分页；MQTT 补发查询排除已过期及直接响应命令，单批最多 500 条。两类游标均保留数据库时间戳的微秒精度，避免高频记录漏页。这些仓储尚未接入运行中的业务入口，当前线上试点的事件去重仍以进程内窗口为准。

2026-10-31 语义对齐：当前 JSON/进程内路径的本地控制事件，即使同时改变负载状态，也只推进一次控制版本；部分状态上报的合并函数现以调用方传入的上一状态为依据，不再隐式读取进程缓存。新增回归测试覆盖变更负载后的重复事件和独立状态快照。该调整为 PostgreSQL 事务接入消除了两条路径的版本差异，但尚未完成设备、命令、事件的整体运行时切换。

运行中 API 尚未接入这些 PostgreSQL 仓储；现有业务仍走 JSON，设备状态及控制版本仍在进程内。运营总览的事件、知识、审计及其他业务读写也尚未统一切换；不能只把设备或命令单独切到 RDS。当前小时级完整状态核对仍会刷新最新状态，但状态无变化时不再新增历史事件，避免固定周期空转写入事件表。

设备身份路径已增加可选的 RDS 凭据模式：HTTP 配置 `DEVICE_AUTH_BACKEND=postgres`，Broker 配置 `MQTT_DEVICE_AUTH_BACKEND=postgres`。两者按设备 ID 查询 `dongxin.device_credentials`，只校验启用设备的随机密钥 SHA-256 摘要；数据库不可用时拒绝认证，不回退到 JSON 开发密钥。Broker 额外限制同时待处理的数据库认证请求数，并保留网关 client ID 的专用认证路径。原有 JSON 模式仅用于至多 20 台设备的受限样机试点。

设备注册现在将型号视为灌装身份属性：已有档案不能通过重新注册改型号；启用 RDS 设备认证时，首轮注册也须与 `dongxin.devices.model` 一致，缺失预置档案则拒绝。设备自报的固件版本和能力仍是观测数据，不构成产品能力授权。在线设备重复注册不再追加相同的注册历史事件；首次登记及离线恢复仍记录。当前本地 JSON 档案每次注册仍需重写，十万台运行必须等设备档案与事件整体切到数据库，不能以这项减写代替生产存储改造。

样机试点的 20 台上限现由 API 启动检查和设备档案写入检查共同执行，包含使用 RDS 设备密钥但业务仍写 JSON 的组合；第 21 台注册或后台批量导入会被拒绝，已有档案不被覆盖。运营平台系统页显示当前占用数。该限制不提供十万台容量，也不能解除正式生产启动门禁。

文本会话的 PostgreSQL 仓储已支持按设备/渠道限定会话、事务性追加单轮文本、按设备分页读取最近对话；单轮输入和回复分别限制为 4000 字符，调用量字段仅允许令牌数、时延、费用等标量指标，不接收原始音频或 Base64 字段。配置 `VOICE_HISTORY_BACKEND=postgres` 后，运行中的设备音频对话及研发文本测试写入该仓储，研发历史页从数据库分页读取；默认仍是本地 JSON。启用前须完成迁移和设备灌装，否则外键会拒绝未登记设备的语音记录。临时多轮上下文仍在单个 API 进程内，RDS 历史只用于追溯，不代表重启后能自动恢复未结束对话，也不代表其他设备/命令/知识业务已完成持久化切换。

过期数据清理命令 `npm run db:retention -w @dongxin/api` 默认仅显示 90 天截止时间和表名单，不连接数据库。带 `--apply --confirm-delete-expired` 可手动对会话文本、会话索引、设备事件、设备命令及员工审计分批删除。API 启用 PostgreSQL 连接后也会在启动时和随后每小时执行同一清理；每表每轮最多 20 批、每批 500 条，关闭服务时等待当轮结束后再关闭连接池。知识库内容、知识库修订、产品配置和设备凭据不在清理名单。首次启用 PostgreSQL 功能前，须在 RDS 上核对执行计划、索引、单批耗时及备份恢复；当前未实际删除云端数据。

灌装命令 `npm run db:provision-device -w @dongxin/api -- --device-id DX-001 --model DX-AI-01 --secret-out /secure/dx-001.json` 仅在已迁移的 RDS 上运行，要求密钥文件路径在 Git 仓库之外且事先创建安全目录。命令使用随机 32 字节密钥，先以独占方式创建权限受限的输出文件，再在同一数据库事务中插入设备档案及密钥摘要；重复设备 ID 会失败，不会覆盖现有密钥。原始密钥文件需由受控灌装工位写入设备，妥善保管或按制度销毁，不能发给前端、写入日志、提交 Git。此命令目前未在真实 RDS 执行。

截至 2026-10-31，运行时自动化测试 95 项、数据库仓储/迁移与灌装测试 37 项、MQTT Broker 鉴权测试 4 项通过，工作区类型检查与构建通过。迁移计划的只读执行列出 `001_core` 和 `002_local_event_identity`，未连接数据库；保留命令的只读计划执行通过。这些数据库测试使用替身，尚未连接阿里云 RDS，也不证明实际 SQL 执行、事务隔离、容量或重启恢复表现。灌装命令只完成代码和事务回滚测试，尚未生成或写入任何真实设备密钥。

## 执行条件

1. 东信确认阿里云账号、杭州 RDS 实例、VPC 内访问地址、数据库名称和专用账号。数据库不开放公网；应用账号只取得业务所需权限，迁移使用单独受控账号。
2. 下载并核验 RDS 的 CA 证书，在 ECS 上以受限文件权限存放。配置 `DATABASE_URL` 和 `DATABASE_CA_FILE`，不把密码或证书写入 Git、前端包或截图。
3. 在已配置 Node 环境的 ECS 上运行 `npm run db:plan -w @dongxin/api`，核对将执行的版本与校验和。此命令不连接数据库。
4. 备份数据库并取得维护窗口后，才运行 `npm run db:migrate -w @dongxin/api`。执行后查询 `dongxin.schema_migrations` 与核心表，复核版本、权限和备份。

## 上线门禁

现有 API 的设备、命令、知识和日志仓储仍主要读写本地 JSON，实时设备状态和语音会话仍有进程内状态。**迁移文件通过静态测试不等于 RDS 实测，也不等于业务已切换。** 在逐项改用 PostgreSQL、完成设备凭据灌装、微信登录/归属校验、TLS MQTT 接入、恢复演练和少量样机压测前，保持 `NODE_ENV=production` 的默认拒绝启动行为。当前仅允许明确限制设备数的单实例样机试点，不允许将本地 JSON 模式当作十万台正式后端。

首轮数据库验收至少包含：断电/进程重启后的设备状态、控制版本、命令和回执保持一致；重复回执幂等；过期命令不再下发；知识审核和审计可追溯；90 天文本留存与批量清理；数据库备份恢复；单设备身份隔离；心跳高峰与语音突发的实际负载数据。
