# 浴霸控制状态机与安全规则 V1.0

文档状态：软件开发基线，热参数待样板标定
适用主控：ESP32-C3
更新日期：2026-09-14

## 1. 基本原则

平台、LLM、CI1302、遥控器都不能直接写 GPIO。所有输入先转成统一命令，由 C3 本地安全状态机做最终裁决。网络断开、服务器故障或 CI1302 故障不应影响过温保护、遥控关机和基本负载控制。

软件安全不能替代硬件温控器、保险丝、电气隔离和额定选型。

## 2. 统一命令模型

```text
command_id       全局唯一，支持幂等
source           CI_OFFLINE / CLOUD / REMOTE / TIMER / SAFETY
intent           设备意图
arguments        温度、时长等结构化参数
created_at       创建时间
expires_at       失效时间
priority         优先级
```

处理顺序：格式校验 → 设备能力校验 → 去重/过期校验 → 当前状态校验 → 安全规则 → 原子更新期望状态 → 驱动层执行 → 读回/确认 → 状态上报。

同一 `command_id` 只能造成一次状态变化。超过有效期的云端命令不得在设备重连后补执行。

MQTT V1.0每个 `command_id` 只允许一个动作，避免多动作中途失败造成部分执行。组合模式由C3内部状态机作为一个语义动作实现，不由平台拼接多个GPIO动作。

## 3. 运行状态

| 状态 | 说明 | 允许的主要输出 |
|---|---|---|
| BOOT_SAFE | 上电和初始化 | 全部危险输出关闭 |
| STANDBY | 待机 | 所有负载关闭 |
| LIGHT_ONLY | 仅照明 | 照明 |
| FAN | 吹风 | 风机 |
| VENTILATION | 换气 | 换气风路 |
| HEAT_WEAK | 弱暖 | 风机稳定后弱暖 |
| HEAT_STRONG | 强暖 | 风机稳定后强暖，禁止弱暖与强暖冲突 |
| CONSTANT_TEMP | 恒温 | 根据标定温度和回差切换取暖档位 |
| DRY | 干燥 | 分段运行，首版热策略受功能开关保护 |
| COOLDOWN | 取暖关断散热 | 取暖关闭，风机继续运行 |
| FAULT_LOCKED | 故障锁定 | 取暖强制关闭；其余能力按故障类型降级 |

照明可与大部分工作状态并存，不作为主模式。摆风是附属状态，只有风机或取暖运行时才允许开启。

## 4. 强制不变量

1. 上电、复位、看门狗重启和固件升级期间，弱暖/强暖驱动始终关闭；
2. 风机未确认运行时不得打开任一 PTC 取暖输出；
3. 弱暖和强暖不允许同时处于互斥错误组合；具体电路若强暖需要两级同时导通，必须在 HAL 内封装，业务层仍只看到一个档位；
4. 吹风与换气如使用同一电机的不同绕组，切换前先全关并等待硬件确认的死区；
5. NTC 断路、短路、读数越界或连续异常时立即关闭取暖并锁定故障；
6. 达到软件过温阈值时立即关闭取暖并进入 COOLDOWN；阈值未完成标定前不得进行带 220V PTC 的无人值守测试；
7. 取暖达到最长连续运行时间后关闭取暖，不允许旧协议中的“无限定时模式”；
8. 关闭取暖后风机继续散热，默认120秒，最终值由热测试冻结；
9. 待机命令关闭所有负载，但如果刚关闭取暖，应先进入 COOLDOWN，散热完成后再进入 STANDBY；
10. 设备能力为 OPTIONAL/NOT_SUPPORTED 时返回 `UNSUPPORTED`，不得静默成功；
11. LLM只能产生结构化建议，不能绕过本地规则；
12. 驱动写入失败、IO扩展器失联或读回不一致时关断危险输出并进入故障状态。

## 5. 上电和失效行为

```text
上电
  → 硬件上下拉保证驱动关闭
  → C3原生LOAD_ENABLE由硬件保持禁用
  → C3初始化状态、NVS和看门狗
  → 初始化100kHz I2C
  → 向0x20/0x21/0x22写入0xFF全关值并逐颗探测
  → 保持LOAD_ENABLE关闭，等待首个通过安全校验的动作
  → 完成 NTC/遥控/CI/WiFi 初始化
  → 进入 STANDBY
```

NVS 只恢复非危险配置，如 WiFi、音量、目标温度和版本信息；上次的取暖、风机、摆风和照明状态不自动恢复。

## 6. 取暖状态机

开启弱暖或强暖：

1. 校验 NTC、硬件故障、最长运行时间和设备能力；
2. 若换气正在运行，关闭换气并等待电机切换死区；
3. 启动风机；
4. 等待风机稳定时间。无转速反馈的首版由样板测试给出固定延时；
5. 再打开相应取暖输出；
6. 开始取暖计时并上报状态。

关闭取暖：

1. 立即关闭全部取暖输出；
2. 保持风机运行；
3. 默认散热120秒；
4. 若期间收到故障或待机，取暖仍保持关闭，风机按故障策略决定是否继续；
5. 散热结束后进入用户期望的 FAN 或 STANDBY 状态。

## 7. 恒温控制

- 目标温度范围30至45℃，默认40℃；
- NTC采样需做合理的中值/低通滤波，不能用单次ADC值直接切换取暖；
- 首版建议采用有回差的分档控制，不采用复杂 PID；
- 建议初始回差为1℃，必须通过样板温升和体感测试确认；
- 传感器位置使读数无法代表环境温度时，界面必须称为“设备温度”或完成换算标定，不得误导为室温；
- 温度超过软件过温阈值的处理优先级高于目标温度控制。

## 8. 干燥模式

无样板热测试前，干燥模式默认只运行风机/换气，不启用 PTC。模式最长60分钟，支持用户提前结束。

样板热测试通过后，可配置“弱暖 + 风机 → 仅风机散热 → 换气”的分段循环。每段时长、循环次数和温度上限作为产品配置，不硬编码在语音或平台逻辑中。强暖不用于无人值守干燥。

## 9. 命令冲突

| 当前状态 | 新命令 | 结果 |
|---|---|---|
| HEAT_WEAK | HEAT_STRONG_ON | 先关弱暖，保持风机，再切强暖 |
| HEAT_STRONG | VENTILATION_ON | 先关取暖并完成必要散热，再切换风路 |
| 任意取暖 | STANDBY | 关取暖，进入 COOLDOWN，最后待机 |
| FAULT_LOCKED | 任意取暖开启 | 拒绝，返回故障原因 |
| STANDBY | SWING_ON | 拒绝或等待风机命令，不单独启动摆风 |
| DRY | 用户普通模式命令 | 停止干燥计划，执行新命令 |
| 播报中 | 新语音输入 | 第一版忽略，遥控关闭和安全事件仍处理 |

## 10. 故障码

| 故障码 | 含义 | 默认动作 |
|---|---|---|
| E001 | NTC断路/短路 | 关闭取暖，故障锁定 |
| E002 | 软件过温 | 关闭取暖，风机散热，故障锁定 |
| E003 | IO扩展器失联 | 拉低驱动总使能，全部危险输出关闭 |
| E004 | 输出读回不一致 | 关闭危险输出，故障锁定 |
| E005 | 风机启动失败/无反馈 | 禁止取暖；仅在有反馈硬件时启用 |
| E006 | 取暖超时 | 关闭取暖，进入散热 |
| E101 | CI1302链路故障 | 禁用语音，遥控和平台控制继续 |
| E102 | CI资源版本不一致 | 禁用离线语义控制 |
| E201 | BLE本地终端链路异常 | 禁用故障终端，其余链路继续 |
| E301 | MQTT离线 | 本地控制继续，恢复后上报完整状态 |

故障清除应按故障类型区分自动恢复和人工确认。过温、输出异常不得仅靠再次语音命令清除。

## 11. 状态上报

状态变化立即上报 MQTT；无变化时低频心跳保活。上报至少包含：

- 期望状态和实际状态；
- 控制来源、命令ID和结果；
- 照明、风机、换气、取暖档位、摆风、干燥；
- 目标温度、传感器温度和传感器有效性；
- 故障码、故障发生时间、复位原因；
- C3固件版本、CI固件版本、CI资源版本；
- WiFi RSSI、在线状态和运行时间。

## 12. 研发验收顺序

1. 纯软件单元测试：状态转换、冲突、幂等、超时和故障注入；
2. C3文本/MQTT模拟：命令进入统一队列并改变虚拟HAL状态；
3. 三颗PCF8574低压LED板：验证上电全关、低有效输出顺序、I2C断线和LOAD_ENABLE独立关断；
4. CI1302模拟：语义ID映射、未命中在线分流、断网提示；
5. 东信空载样板：不接220V，以LED/测试点观察输出；
6. 东信安全台架：由硬件人员接入实际负载，验证互锁和硬件保护；
7. 温升/长稳：连续运行、频繁切换、断网、重启和异常恢复；
8. 冻结阈值和时序后形成量产配置。
