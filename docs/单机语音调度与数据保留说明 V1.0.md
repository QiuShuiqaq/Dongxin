# 单机语音调度与数据保留说明 V1.0

更新日期：2026-11-02  
适用范围：当前单服务器、单 API 进程的研发及部署准备代码

## 1. 调度与超时

设备请求优先于研发批量任务。同一设备在各队列内按先后顺序处理，不同设备共享并发槽位；消息优先级不得改变同一设备先前已入队消息的顺序。

当前阶段采用16路在线语音处理上限；后续扩容根据实际联调、带宽、模型额度与成本评估另行决定。离线固定指令由CI1302与STM32本地处理，不占用云端语音队列，也不因在线服务可用或繁忙而关闭。

| 环节 | 默认执行数 | 默认等待数 | 最长排队 | 执行期限 |
|---|---:|---:|---:|---:|
| 整条语音任务 | 16 | 4 | 500毫秒 | 10秒，包含入队等待及全部AI阶段 |
| ASR、LLM、TTS各阶段 | 各16 | 各4 | 500毫秒 | 各10秒，并受整条任务剩余期限约束 |
| MQTT上行处理 | 4 | 256 | 5秒 | 由具体处理流程约束 |
| 研发批量任务 | 最多2个运行批次 | 不设置无限批次队列 | 满载拒绝 | 每条受阶段期限约束 |

同设备语音默认最多等待1条，AI阶段最多2条，MQTT上行最多16条。队列满或等待超时返回繁忙；HTTP 429 附带 `Retry-After`。设备端应有限次退避重试，不立即循环重发。

16路表示服务端同时执行的整链路任务上限，4条等待任务不计入执行数；阶段并发不会使整链路变成48路。单项ASR、LLM、TTS测试也受对应阶段限制。整条语音任务从进入服务端调度开始计时，内部阶段排队不延长总预算；该预算不包括设备录音、请求到达调度前的上传时间和扬声器播放时间。独立AI测试的阶段执行时限从获得阶段槽位开始计算。

超时、停止测试后向下游传播取消信号；仍未结束的调用继续占用槽位，直到实际返回或失败。回调不得在超时后再提交设备动作。取消本地等待不保证服务商停止计费。

以上是软件限制值，不是硬件容量结论，也不代表当前5Mbps出口能保证16路完整语音同时满足响应目标。预计首年10万台设备不等于10万路同时语音；上线容量需根据实际设备心跳、在线数、音频传输量及服务商限额测量。

## 2. 在线控制失效与确认

语音请求进入排队前记录设备控制版本，安全校验和下发前再次检查；本地状态变化、故障变化或 `LOCAL_CONTROL` 事件会使旧控制失效。心跳和模式列表顺序变化不触发控制版本变化。

安全规则拒绝的结果不会变成下发动作。需要确认时，仅保存待确认记录，首次响应不返回动作；用户确认后再次检查设备版本、期限和安全规则。旧确认不能在本地操作后恢复执行，也不能重复使用。

真实设备侧的控制序号与最终仲裁尚待 CI1302 接入时补齐。服务端在收到本地事件前不能知道本地新动作，不能消除网络延迟窗口内的全部冲突。

## 3. 降低重复调用

既有规则、精确FAQ可绕过LLM；需要开放推理时仍调用LLM。保留既有知识库检索及审核发布流程。

- HTTP设备语音支持 `X-Request-Id`，同设备同请求编号在短窗口内复用结果；内容不同返回409。窗口默认256条、响应4MB、60秒；单个大于128KB的响应仅共享在途请求，不长期缓存。含直接动作的响应在每次返回时检查控制版本和有效期，防止缓存重试重新返回失效动作；普通对话仍可复用。
- MQTT上行按设备、消息类型和消息编号去重；最多2048条、1MB、60秒；单消息上限64KB。
- 短文本TTS（不超过200字符）使用内存缓存，默认8MB、15分钟、最多64条，单条不超过512KB；缓存键包含服务、音色及合成参数。人工选择的语速、音色不会混用缓存。
- 短回复缓存不保存麦克风录音；长回复仍正常合成。已有取消上下文的请求不共享跨任务的在途合成，避免停止一个任务影响另一个。

这些机制均有容量和有效期边界，不是永久幂等记录，也不是持久消息队列。重启后不会自动恢复语音任务。

## 4. 调用量与费用

`runtime-ai-usage.json` 持久记录UTC当日ASR、LLM、TTS尝试次数、失败数及估算费用。进入真实服务商调用前预留次数，服务重启不直接清零。规则命中、缓存命中及MOCK模型不计为真实模型调用。

`ASR_DAILY_CALL_LIMIT`、`LLM_DAILY_CALL_LIMIT`、`TTS_DAILY_CALL_LIMIT`为每日次数上限；`AI_DAILY_ESTIMATED_BUDGET_CNY`为估算费用阈值，0表示关闭对应限制。费用依赖已配置单价，以服务商账单为准；在途调用、失败请求的服务商收费及未配置单价可能导致估算与实际不同，费用阈值不是精确的账单硬封顶。

## 5. 数据保留

默认文本保留不超过90天，同时受全局数量上限约束，高频写入可能使数据早于90天清理。

| 数据 | 默认数量上限 |
|---|---:|
| 研发对话历史 | 1000个会话，每会话200轮 |
| 语音测试记录 | 100个会话，每会话100轮 |
| 设备事件 | 500条 |
| 控制命令 | 500条 |
| 系统日志 | 1000条 |

写入时执行限制，启动及每小时进行白名单维护。知识库、产品配置及人工选定的ASR测试集不属于自动清理范围。批量测试交付产物应另行导出归档，运行历史不作为长期档案。

日常麦克风音频不落盘。语音测试记录写入时去除内联TTS音频；短回复音频缓存及设备下载资产只在内存短期存在。人工归档到ASR数据集的录音为明确保留的实验资料，需单独管理。

JSON文件使用同进程串行事务与临时文件原子替换，降低并发写入覆盖风险。这不提供多进程或多服务器事务，也不构成10万台规模的生产数据库方案。当前不增加Redis或第二台服务器；生产持久层迁移及容量测试另行执行。

## 6. 配置与查看

参数示例位于 `apps/api/.env.example`。队列并发和长度在服务启动时初始化，修改后重启API；运维人员应把相关参数作为一组部署配置管理，不在运行中只修改部分参数。

运营平台 → 系统状态 → “语音调度与调用量”“缓存与数据保留”，每30秒刷新。展示执行中、排队、成功失败、拒绝、等待超时、取消、MQTT去重、调用量、估算费用及最近清理状态。

接口为 `GET /api/operations/runtime`，同时随运营总览数据返回运行状态。启用员工鉴权时沿用现有访问控制。设备HTTP独立凭据入口已准备，正式HTTPS、密钥下发和固件认证仍需部署联调，不能直接对公网开放本地开发配置。

## 7. 软件验证入口

在项目根目录使用本项目Node环境运行：

```powershell
npm.cmd run typecheck
npm.cmd run verify:runtime
```

链路测试替换外部服务和设备动作；持久化测试使用D盘独立临时目录，验证真实文件事务，不修改项目运行数据。覆盖队列边界、设备消息顺序、请求去重、缓存期限、取消和超时、本地操作使旧指令失效、确认安全及语音会话回归。通过这些测试不代表真实硬件、声学效果、服务商并发额度或生产容量已经验证。
