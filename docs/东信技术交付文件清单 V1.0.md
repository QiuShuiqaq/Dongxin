## 2. 东信交付给软件侧

### 投板前

- 原理图PDF、可编辑工程和完整C3引脚表；
- BOM及关键器件完整料号；
- CI1302数据手册、SDK、烧录工具、资源生成工具和参考工程；
- CI1302厂商UART消息、I2S示例与本项目协议的映射表；
- 墙面触控板和手持遥控器的BLE芯片、SDK、烧录工具及量产报价；
- NTC料号、25℃阻值、B值、公差、分压和安装位置；
- 摆叶电机、电机驱动、风机、PTC、继电器/可控硅参数；
- 温控器、保险丝、隔离、EMC及认证责任说明；
- 显示/11触摸键、夜灯、净化的装配决定。

### 样板到件时

- 建议5块有唯一编号的样板；
- C3和CI1302烧录线/治具；
- 至少一块支持不接220V观察输出；
- 已预绑定的BLE墙面触控板和手持遥控器；
- 样板版本和已知问题；
- 接真实负载时由东信硬件人员提供安全台架和操作。

## 3. 软件侧阶段性交付

### P0：协议与虚拟验证

- 产品硬件能力配置；
- CI1302语音配置版本、唤醒词、命令和语义ID；
- CI1302事件模拟；
- 统一设备意图和 `UNSUPPORTED` 拒绝；
- MQTT设备注册、命令、状态和结果闭环；
- 文本语音链路及成本记录；
- 架构、协议、安全和样板文档。

验收证据：TypeScript检查、前后端构建、API用例、MQTT smoke、C3串口日志和平台截图。

### P1：C3低压控制固件

- 统一命令队列；
- 安全状态机；
- 虚拟HAL和3颗PCF8574驱动；
- NTC抽象和故障注入；
- BLE墙面板/遥控器GATT、绑定、命令回执和状态同步；
- CI1302 UART控制帧、ACK、重试、I2S PCM和链路状态；
- 状态变化立即上报和低频心跳；
- C3/S3可构建工程及分区表。

验收证据：单元/桌面模拟、C3开发板日志、低压LED/逻辑分析仪波形。

### P2：东信样板联调

- 样板引脚配置；
- CI厂商SDK适配；
- 遥控码表；
- NTC曲线和温控参数；
- 电机参数；
- 负载互锁、散热和干燥节拍；
- 故障码和生产自检；
- 8小时功能压力及24小时联网测试报告。

### P3：量产候选

- 固件版本号、Git提交、构建环境锁定；
- bootloader、partition table、application及合并烧录文件；
- CI固件和资源包、SHA-256；
- 量产烧录参数和治具协议；
- 设备唯一密钥注入方案；
- 发布说明、已知限制和回滚包；
- 生产平台部署、监控、备份和数据保留配置；
- 小程序配网、绑定和单设备控制。

## 4. 每个固件版本必须包含

| 项目 | 要求 |
|---|---|
| 版本标识 | 产品型号、C3固件、CI固件、CI资源四个版本 |
| 源码基线 | Git提交ID，不接受只有bin没有源码基线 |
| 构建说明 | ESP-IDF版本、目标芯片、命令和分区表 |
| 二进制 | 分地址文件和合并烧录文件 |
| 哈希 | 所有发布二进制的SHA-256 |
| 配置 | 功能能力、引脚、温控、遥控和服务器环境 |
| 测试 | 自动化结果、样板编号、日志和未通过项 |
| 变更 | 新功能、修复、不兼容变化和回滚办法 |

密钥、WiFi密码和生产凭证不得写入源码或通用bin。每台设备使用独立 `deviceSecret`，由生产流程安全注入。

## 5. 平台生产化交付

研发期平台使用本地MQTT和JSON数据。生产部署前必须补齐：

- 东信内部后台账号密码，可选微信扫码登录；
- 普通消费者微信小程序入口，以及遥控器本地入口；
- BLE配网和机身二维码首次绑定；
- 单设备单归属，第一版不做家庭/多人共享；
- 阿里云IoT设备身份、Topic权限和每机密钥；
- RDS PostgreSQL/MySQL数据迁移；
- Redis缓存、限流和短期会话；
- 设备、用户、产品、版本、命令、告警和审计模型；
- 文本日志默认90天自动清理，不保存原始音频；
- 灰度发布、监控告警、数据库备份和灾难恢复。

这些属于平台生产化阶段，不阻塞P0/P1样板开发，但在10万台量产接入前必须完成容量和安全评审。

## 7. 当前不应承诺为完成

- 未拿到样板时不能宣称真实负载控制完成；
- 未拿到CI1302 SDK和资源工具时不能宣称离线语音量产完成；
- 未完成温升测试时不能冻结软件过温阈值和干燥加热节拍；
- 未选定墙面板/遥控器BLE芯片和SDK时不能宣称本地终端量产完成；
- 本地MQTT/JSON跑通不等于阿里云10万台生产系统已完成；
- 软件关断验证不等于220V电气安全和认证完成。
