# 东信样板硬件接口及验收要求 V1.0

交付对象：东信硬件、结构和测试人员<br>
文档状态：画板输入基线，具体 GPIO 待原理图评审冻结<br>
更新日期：2026-09-14

## 1. 样板目标

样板用于验证 ESP32-C3 直接承担浴霸唯一业务主控。首板必须支持不接 220V 完成 C3、CI1302、三颗 PCF8574、NTC、雷达、墙面触控板、手持遥控器和低压输出联调，再由东信具备电气安全条件的人员连接真实负载。

ESP32-S3 只保留研发对照，不是本次首板基线。旧独立 MCU 不装入新样板。

## 2. 必选器件

| 模块 | 基线 |
|---|---|
| 主控 | ESP32-C3，Flash 不低于 8MB，预留 A/B OTA 分区 |
| 语音 | CI1302 + 外部晶振，按启英泰伦麦克风、DAC/功放和电源参考设计 |
| IO扩展 | 3 x PCF8574，地址 0x20/0x21/0x22，I2C 100kHz，共 24 路 |
| 本地控制 | 主板使用 C3 内置 BLE；墙面板和手持遥控器各自配置 BLE 芯片 |
| 温度 | NTC + 分压/滤波，接 C3 原生 ADC |
| 人感 | 雷达/人感，首选数字存在信号接 PCF 输入 |
| 负载使能 | C3 原生 GPIO 独立控制 `LOAD_ENABLE`，硬件默认关闭 |
| 调试 | C3、CI独立烧录；UART、I2S、I2C、INT、ADC、使能和输出测试点 |
| 安全 | 温控器、保险丝、隔离、功率驱动、EMC 和认证由东信负责 |

C3 侧不再放置 ES8311 等重复音频 Codec，不增加外部 BLE 接收模块。PCF8574 只连接低压逻辑和驱动输入，禁止直接带继电器线圈、电机、PTC 或市电负载。

## 3. C3 原生资源预算

具体 GPIO 编号由东信提交原理图后冻结，投板前至少保证：

| 接口 | 资源 |
|---|---:|
| CI1302 UART0 | 2 GPIO |
| CI1302 I2S 双向 PCM | 4 GPIO，另预留 MCLK 1 GPIO |
| PCF8574 I2C | 2 GPIO |
| `LOAD_ENABLE` | 1 GPIO |
| 三颗 PCF 共用 `INT_N` | 1 GPIO |
| NTC ADC | 1 ADC GPIO |
| C3 USB Serial/JTAG | GPIO18/19，建议保留 |

BLE 不占外部 GPIO。雷达优先接 PCF 输入；如果最终雷达必须 UART，再单独评审 GPIO 和 UART 复用。不得占用 Flash 引脚，启动绑带脚的上下拉必须与外设默认电平兼容。

这个预算在 C3 上可实现，但余量有限。原理图必须附“GPIO号、上电方向、默认电平、启动绑带、复用功能、测试点”完整表，不接受只写 SDA/SCL 而不列其余接口。

## 4. C3 与 CI1302

- UART0：3.3V TTL、115200bps、8N1，TX/RX交叉并共地；
- I2S：16kHz、16bit、单声道，预留 BCLK、LRCLK/WS、双向DATA和MCLK；
- CI1302 必须使用外部晶振；
- 首选 C3 为 I2S Master，但必须在投板前用官方 SDK 示例确认；
- CI_RESET、BOOT/升级脚、UART0和I2S全部提供测试点；
- CI进入厂商烧录模式时，C3不得向UART0发送项目数据；
- 双方电源时序需防止 IO 反向供电；
- 麦克风、DAC、功放、扬声器、电源滤波和布局遵循启英泰伦参考设计。

详细消息语义见《ESP32-C3与CI1302通信协议 V1.0》。

## 5. PCF8574 总线和失效设计

- 同一 I2C 总线挂载 U1/U2/U3，地址固定 `0x20/0x21/0x22`；
- A0/A1/A2 必须硬件固定，不能悬空；
- 总线 100kHz，使用外部上拉；阻值按电压、线长和总线电容计算；
- 三颗 `INT_N` 可线与后接一个 C3 原生中断 GPIO，也必须允许轮询排障；
- PCF8574 无 RESET 和方向寄存器，上电端口为准双向高电平；
- 所有负载输出采用“PCF 输出低才表示有效”的低有效设计；
- 输入位在软件影子值中始终写 1；
- C3 未启动、复位、I2C失联或软件异常时，独立 `LOAD_ENABLE` 必须由硬件默认禁止危险驱动；
- 每个输出都提供低压 LED 或测试点；LED极性不能让上电高电平变成负载有效；
- PCF读回只证明总线和引脚电平，不等同于继电器/负载已真实动作。

## 7. NTC、雷达和本地终端

### NTC

东信需提供料号、25℃阻值、B值、公差、分压电阻、安装位置和ADC保护电路。软件过温阈值在温升测试前保持未冻结。ADC需要校准、滤波、开路/短路检测，并验证 WiFi 和功率开关噪声。

### 雷达/人感

首选一个数字存在信号接 U3 输入。若模组需要 UART、PWM 或模拟量，需在投板前提交协议和电平。雷达结果第一版只做状态/策略输入，不能绕过安全规则直接开取暖。

### 墙面触控板与手持遥控器

两者通过 BLE 连接 C3，发送语义命令并接收真实状态。墙面板本地驱动屏幕和触摸键，不把显示总线或触摸扫描线拉到浴霸主板。终端 BLE 芯片必须支持 Central、加密 Bonding、自定义 GATT 和每套密钥注入。

详细协议见《ESP32-C3与BLE本地控制终端协议 V1.0》。

## 8. 负载和硬件安全

| 输出 | 上电默认 | 软件约束 | 硬件约束 |
|---|---|---|---|
| 照明 | 关 | 独立开关 | 低压逻辑经合规驱动 |
| 吹风 | 关 | 取暖前先开，取暖后散热 | 额定电流、堵转保护 |
| 换气 | 关 | 与取暖和共用绕组互锁 | 禁止冲突绕组同时导通 |
| 弱暖 | 关 | 风机预启动后开启 | 独立温控器和保险丝 |
| 强暖 | 关 | 风机预启动后开启 | 同上，明确PTC级数逻辑 |
| 摆风 | 关 | 有风路才允许 | 专用电机驱动和堵转考虑 |
| 可选负载 | 关 | 未装配返回UNSUPPORTED | 悬空时不得误触发 |

软件关断不能替代温控器、保险丝、隔离、爬电距离、接地、EMC 和认证。220V相关设计及测试由东信硬件负责人签字。

## 9. 原理图评审输入

投板前需提供：

- PDF原理图、可编辑工程、BOM和完整引脚表；
- ESP32-C3模组/芯片、Flash容量、天线净空和USB/烧录接口；
- CI1302参考电路偏差、外部晶振、音频器件和独立烧录；
- UART/I2S主从、方向、测试点和电源时序；
- PCF地址、外部上拉、共享INT和低有效输出；
- `LOAD_ENABLE`硬件默认关闭和危险驱动总使能逻辑；
- NTC、雷达、电机、风机、PTC、继电器/可控硅完整料号；
- BLE墙面板/遥控器芯片、供电、天线、烧录和量产配对方法；
- 温控器、保险丝、隔离、爬电距离、接地和EMC说明；
- 不接220V观察所有关键输出的方法。

软件侧只审核接口可开发性，不替代电气安全评审。

## 10. 首批样板

建议 5 块并编号：

| 数量 | 用途 |
|---:|---|
| 1 | 纯低压、烧录、测试点和故障注入 |
| 1 | CI1302音频和8小时并发压力 |
| 1 | 三颗PCF、NTC、雷达、电机和BLE终端联调 |
| 1 | 东信安全台架真实负载和温升 |
| 1 | 回归及备用 |

至少一块必须支持完全断开 220V 功率级，以 LED/测试点观察照明、风机、换气、弱暖、强暖、摆风及 `LOAD_ENABLE`。

## 11. 验收 Gate

| Gate | 通过条件 |
|---|---|
| H1 原理图 | 文件齐全、资源无冲突、危险输出默认关、双方评审后再投板 |
| H2 纯低压 | C3/CI独立烧录，三颗PCF可寻址，上电所有输出关闭 |
| H3 接口 | UART/I2S语音、BLE终端、NTC、雷达、电机和LED输出通过 |
| H4 安全台架 | 互锁、温控器、保险丝、急停、开短路、I2C失联关断通过 |
| H5 长稳 | 8小时功能压力和24小时联网/待机无误动作、泄漏或异常复位 |
| H6 热参数 | 温升、热点、回差、散热、最长运行和干燥节拍冻结 |

## 12. 直接判定不通过

- 上电、C3复位或PCF异常时取暖输出出现有效脉冲；
- I2C失联后 `LOAD_ENABLE` 无法独立关闭危险输出；
- PCF地址冲突、A0/A1/A2悬空或没有外部上拉；
- C3原生引脚预算不足且原理图未评审；
- C3/CI不能独立烧录和恢复；
- CI I2S主从未由官方SDK证明即投板；
- 未绑定BLE终端能够控制设备；
- 不接220V无法观察关键输出；
- 未提供NTC/电机/负载参数却要求冻结量产固件；
- 仅靠C3软件承担过温保护；
- 原理图未经确认直接投板导致接口无法实现。
