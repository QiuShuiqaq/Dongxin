# 东信智能浴霸 AI 项目 - 固件开发推进计划

> 状态：历史方案，仅保留背景参考。本文中的独立浴霸MCU、C3/S3自带Codec和WakeNet路线均不再执行。当前以 `../../docs/项目范围与技术决策基线 V1.0.md`、`../../docs/研发实施与验证路线图 V1.0.md` 和 `../README.md` 为准。

## 📋 项目目标

在 6 周内完成 ESP32-C3/S3 固件开发，实现智能浴霸与 QiuAI AI Gateway 的完整对接，完成真实样机联调和现场演示。

---

## 🎯 总体架构

```
用户语音输入
    ↓
ESP32 WiFi模块 (本固件)
    ├─ 麦克风采集 + 本地唤醒
    ├─ 在线ASR识别 (WiFi上传音频)
    ├─ HTTPS+JSON 与 QiuAI Gateway 通信
    ↓
QiuAI AI Gateway (已完成)
    ├─ LLM 意图识别
    ├─ 安全规则校验
    ├─ 生成控制指令 + 回复文本
    ↓
ESP32 WiFi模块
    ├─ 接收控制指令 + TTS文本
    ├─ UART 32字节固定帧 → 浴霸主控板
    ├─ TTS 语音播报
    ↓
浴霸主控板 MCU (东信负责)
    └─ 执行照明/取暖/换气等动作
```

#### 3.2 音频采集验证 (Day 12-13)

**任务**:

2. 采集 3 秒音频数据

**验收标准**:

#### 3.3 在线 ASR 集成 (Day 14-15)

**任务**:
1. 用户说话后，麦克风采集音频
2. 将音频 Base64 编码后 POST 到 `/api/device/v1/voice-turn`
3. 后端调用阿里云/百度/豆包 ASR 识别
4. 返回识别文本 + 控制意图

**实现方式**:
```c
// voice_engine.c
void voice_engine_handle_speech(const uint8_t* audio_data, size_t len) {
    // 1. Base64 编码音频
    char* base64_audio = base64_encode(audio_data, len);

    // 2. 构造 JSON 请求
    cJSON* request = cJSON_CreateObject();
    cJSON_AddStringToObject(request, "deviceId", device_id);
    cJSON_AddStringToObject(request, "audioBase64", base64_audio);
    cJSON_AddStringToObject(request, "mimeType", "audio/pcm");

    // 3. POST 到后端
    http_client_post("/api/device/v1/voice-turn", request);

    // 4. 解析响应
    // response.data.replyText -> TTS 播报
    // response.data.actions -> UART 控制
}
```

**验收标准**:
- [ ] 说"打开照明"，后端识别文本正确，照明打开
- [ ] 说"我有点冷"，后端识别为 HEAT_WEAK_ON 意图
- [ ] 说"关闭所有"，浴霸进入待机模式

#### 3.4 TTS 播报实现 (Day 16-17)

### 🟣 阶段四：高级功能与优化 (第5-6周)

**目标**: 实现主动沟通、小程序对接、成本优化

#### 4.1 主动沟通实现 (Day 19-21)

**场景 1: 有人进入浴室**
```
雷达/人感检测到有人
  ↓
主控板通过 UART 上报事件
  ↓
C3 POST /api/device/v1/events (eventType: OCCUPANCY_ENTER)
  ↓
后端判断：温度 < 20°C
  ↓
返回 proactive.replyText: "你来啦，浴室有点凉，要不要开个弱暖？"
  ↓
C3 TTS 播报 + 等待语音确认
  ↓
用户说"好的" → 执行弱暖
用户说"不用" → 取消
```

**验收标准**:
- [ ] 进入浴室时自动问候
- [ ] 温度低时主动建议开暖风
- [ ] 强暖运行 > 30 分钟时主动提醒

#### 4.2 小程序对接 (Day 22-23)

**任务**:

2. 小程序查询设备状态 (GET /api/devices/:id/state)
3. 小程序远程控制 (POST /api/devices/:id/control)
4. 小程序 AI 对话 (POST /api/chat)

**验收标准**:
- [ ] 小程序能看到设备实时状态（温度、湿度、开关状态）
- [ ] 小程序点击按钮能控制浴霸
- [ ] 小程序 AI 对话框能完成自然语言控制

#### 4.3 离线命令优化 (Day 24-25)

**目标**: 降低 LLM 调用成本

**方案**:
- 固定命令不上传 ASR，直接本地识别
  - "打开照明" → 直接发送 UART 帧
  - "关闭所有" → 直接进入待机
- 后端规则引擎优化
  - 常见表达映射到固定意图 (不调用 LLM)
  - "有点冷" → rule: HEAT_WEAK_ON
  - "太热了" → rule: HEAT_OFF

**成本对比**:
- 纯 LLM: 每次 0.0003 元 × 10次/天 × 365天 = 1.1 元/年
- 离线 + 规则: 仅复杂意图调用 LLM → 0.3 元/年 (省 70%)

**验收标准**:
- [ ] 后端统计显示规则命中率 > 60%
- [ ] LLM 调用率 < 30%
- [ ] 平均响应延迟 < 1 秒
