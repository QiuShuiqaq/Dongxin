# 东信智能浴霸固件板级开发推进说明

更新日期：2026-09-14

## 1. 板级定位

| 板型 | 用途 | 状态 |
|---|---|---|
| ESP32-C3 SuperMini HW-466AB | WiFi、MQTT、命令队列和虚拟HAL开发 | COM3实板MQTT闭环已通过 |
| 东信C3 + CI1302样板 | 量产候选硬件和真实功能验收 | 等东信按接口文档设计 |
| ESP32-S3-N16R8 | 资源/稳定性对照和量产备选 | 构建已通过，保留 |

C3是唯一业务主控。CI1302是语音前端，不直接控制负载。旧浴霸MCU串口链路已经退出新样板架构，只作旧产品兼容和协议测试。

## 2. 无样板阶段

按以下顺序实现：

1. 统一命令结构和队列；
2. 安全状态机；
3. 虚拟 `direct_control_hal`；
4. 上电全关、风机/取暖互锁、散热、超时和故障注入测试；
5. CI1302 UART控制帧、CRC、ACK、重试和事件状态机，以及I2S PCM；
6. 用研发平台模拟CI语义ID、离线未命中和断网；
7. C3 SuperMini运行MQTT到虚拟HAL的8小时压力测试。

虚拟HAL允许继续开发，但不代表真实负载已经完成。

## 3. 样板前置输入

东信投板前必须提供原理图和完整引脚表。软件侧需要确认：

- C3至少8MB Flash和A/B OTA分区；
- CI1302 UART0为3.3V、115200bps，I2S为16kHz/16bit/单声道，外部晶振、TX/RX、时钟、数据和复位有测试点；
- 3颗PCF8574使用100kHz I2C和地址0x20/0x21/0x22，危险负载另有C3原生LOAD_ENABLE；
- 所有危险输出在高阻、复位和I2C失联时默认关闭；
- NTC型号、B值、分压和安装位置；
- 墙面板/手持遥控器BLE芯片、GATT能力、量产配对和按键语义；
- 摆叶电机和驱动参数；
- C3/CI独立烧录接口；
- 不接220V也能观察输出的LED或测试点。

具体要求见 `../../docs/东信样板硬件接口及验收要求 V1.0.md`。

## 4. 样板到件后的顺序

### 4.1 纯低压

1. 目检、电源短路和电压检查；
2. 分别烧录C3和CI1302；
3. 验证C3复位期间所有输出关闭；
4. 验证CI HELLO、资源版本、Wake、VAD和语义事件；
5. 验证3颗PCF8574全关、单路低有效输出、读回、共享INT和断线关断；
6. 验证NTC固定电阻、BLE终端配对/语义/回执/状态同步和摆风电机；
7. WiFi、MQTT、音频和IO并发压力。

### 4.2 真实负载

由东信硬件人员在安全台架执行：照明 → 吹风 → 换气 → 摆风 → 弱暖 → 强暖 → 恒温 → 干燥。

每一步都验证开、关、异常中止、断电重启和状态上报。取暖测试必须先证明风机互锁和独立硬件温断有效。

## 5. CI1302语音顺序

```text
麦克风/CI1302
  → 小东小东唤醒
  → 固定命令：语义ID给C3，本地安全执行，提示音反馈
  → 未命中：I2S PCM给C3并提交在线ASR
  → ASR → 规则/知识库/LLM → 安全校验
  → 控制命令或TTS音频
  → C3执行控制 / I2S PCM交给CI1302播放
```

产品统一唤醒词和命令不能通过普通后台保存后立即生效，必须生成CI资源包并完成样机验证、审核和发布。个人唤醒词使用CI设备旁自学习。

## 6. 工具

无需单独采购麦克风、扬声器和功放模块，东信完整样板提供音频硬件。开发侧建议准备：

- 3.3V USB-TTL（CP2102N或CH343）；
- 8通道、24MHz以上逻辑分析仪；
- 数字万用表；
- 母对母、母对公杜邦线；
- 样板配套烧录线/治具。

## 7. 参数冻结

以下内容只能根据最终样板实测写入量产profile：GPIO编号、IO扩展映射、NTC曲线、过温阈值、风机稳定时间、换气切换死区、电机相序/节拍、散热时长、干燥节拍、遥控码和CI SDK消息映射。

S3只有在C3出现明确资源、稳定性或BOM问题时才执行同用例对照，不凭主观判断切换。
