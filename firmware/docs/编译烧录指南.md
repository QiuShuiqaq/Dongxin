## 每次验证顺序

1. 先启动根目录的 `npm run dev`，确认 API 健康检查和 MQTT Broker 正常。
2. 编译并烧录 C3，串口应看到 WiFi、MQTT connected 和 `UART protocol V0.2 self-test passed`。
3. 执行 `npm run mqtt:smoke`，确认模拟设备闭环仍为 `APPLIED`。
4. 在后台向 `DX-C3-SUPERMINI-HW466AB-001` 下发 `LIGHT_ON`，确认 C3 回传命令结果。
5. 未接主控板或 USB-TTL 前，保持 `DX_ENABLE_UART_BRIDGE 0`；此时 `APPLIED` 代表文本模拟，不代表物理灯光动作。

## UART 物理联调前置条件

- 只允许 3.3V TTL；5V TTL 必须加双向电平转换，RS-485 必须加收发器。
- C3 UART1 基线为 TX GPIO4、RX GPIO5，双方必须共地。
- 启用 `DX_ENABLE_UART_BRIDGE 1` 后，设备命令会等待 MCU ACK：首次 500ms，无 ACK 时使用同一序号重试一次，最多等待 2 秒。
- 只有 ACK 结果码 `0x00` 才上报成功；拒绝、非法帧或超时均上报失败。
- 首次测试只接通信线，不接浴霸强电负载。

## S3 编译验证

S3 使用独立构建目录，不覆盖 C3：

```powershell
cd D:\workspace\Dongxin\firmware
& $idf $idfPy -B build-s3-verify2 -D SDKCONFIG="$PWD\sdkconfig.s3" set-target esp32s3
& $idf $idfPy -B build-s3-verify2 -D SDKCONFIG="$PWD\sdkconfig.s3" build
```

S3 当前启用 16 MB Flash 和 8 MB Octal PSRAM，启动时会校验 PSRAM 容量，并完成板级 I2C 扫描。音频驱动待实际麦克风、Codec 和功放型号确认后接入；该镜像只适用于 N16R8 板型。
